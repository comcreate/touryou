# HTML 画面の、実ブラウザでの確認

CI にはブラウザを入れない（依存になるため）。画面を変えたら、手元で次を実行して確かめる。Playwright は依存に加えず、環境にあるものを使う。

```sh
pnpm build
TOURYOU_PLAYWRIGHT=$(npm root -g)/playwright TOURYOU_OUT=/tmp/ui node scripts/ui-browser-check.mjs
```

`TOURYOU_CHROMIUM` で実行ファイルを変えられる（既定 `/opt/pw-browsers/chromium`）。スクリプトは、daemon の窓口を、種になる状態（子の報告・判断要求に、スクリプトタグと `onerror` の文字列を入れる）で立てて、明・暗の両方で開く。

## 表示と接続

| 項目 | 期待 |
| --- | --- |
| `/ui#token=…` で開く | 読み込み後、アドレスにトークンが残らない |
| 子が書いた文字列に `<img onerror>`・`<script>` | 実行されず、文字として表示される。`window.__xss` が立たない |
| コンソールのエラー・ダイアログ | なし（CSP に違反しない） |
| 貼り付けの入力欄 | トークンなしで開くと出る。誤ったトークンで「正しくありません」。正しいトークンで接続 |
| SSE で接続 | 表示が「SSE」 |
| 状態の変化の反映（SSE） | 2 秒以内（NFR_008） |
| SSE が使えない（429） | 「ポーリング」に切り替わり、ETag で 200 のあと 304 |
| 429（Retry-After 5 秒） | その秒数より前には、SSE に再接続しない |
| 通知が続いても、取り直しは最短 1 秒ごと | 3 秒の間に 30 回変えても、状態の取得は 3〜4 回 |
| SSE が切れる（1 回目の接続を中断） | 指数バックオフで再接続し、「SSE」に戻る |
| ETag・304 | 変化がない間は 304（本文なし。描き直さない）、変わった直後は 200（新しい ETag） |
| 人間以外のトークン（403） | 「人間のトークンが必要です」（401 の「正しくありません」と分ける） |
| `constructor` という名前のノード | 木に出る（表の引き当てを間違えない） |
| 明・暗の配色 | どちらも読める |

## 操作

daemon の窓口の実物に、記録するだけの仮のハンドラ（`decision.answer`）を付けて確かめる（`out.operations`）。

| 項目 | 期待 |
| --- | --- |
| 選択肢で回答 | 押しても、すぐには送らない。確認に、質問と回答が出る。「戻る」で閉じる |
| 二重クリック | 「この内容で送る」を二重クリックしても、要求は 1 回 |
| 自由入力 | 空・制御文字は、確認に進まず、理由が出る。複数行は、確認に全文が出る |
| 入力中の再描画 | 状態が更新されても、入力中の文が残る |
| 失敗 | `code: cause` が出て、確認に戻る。同じ内容で再送でき、**同じ requestId** |
| 長い質問・長い選択肢 | 質問は 2,000 文字まで読め、超えたら「…（省略）」。長い選択肢のボタンは無効で、自由入力を促す。確認にも長い質問が出る |
| 429（Retry-After 2 秒） | 「あと N 秒待つ」で、送れない。時間が来たら、押せるようになり、送れる |
| XSS（質問・選択肢） | 確認画面でも、実行されない |
| 拡張要求の承認 | 対象（`src/ok.ts`）が、カードと確認に出る。送るのは `extensionId`・`decision` だけで、1 回 |
| 最終削除 | 事前確認の内容（ノード数・墓標・保管の数）が確認に出る。根の ID を打ち込むまで送れない（前後の空白・大文字・全角は不一致）。一致すれば送れ、送る params は `nodeId` だけ |
| 実行できない木 | 理由が出て、打ち込みの欄もなく、送れない |
| 保留（30 日） | 打ち込みなしの確認。期限は ISO 8601 UTC で、約 30 日後 |
| 保留の日数 | 範囲外（400 など）は、理由が出て確認に進まない。45 日は、確認に期限が出て、その期限で送る。365 日は、10 分短い期限で送る |
| 保管の一覧・削除 | 読み込むまで出ない。件名の制御文字は除かれる。key を打ち込むまで削除できず、`expectTip` が一覧の先端で送られる。削除後は読み込み直される |
| 隠れた対象（`../outside/secret`） | 値は画面のどこにも出ない。承認・切り出しは無効で、却下だけ押せる |
| 回収の指示のボタン | 停止したノードで、指示済みでないものだけ。指示済みには「破棄を指示済み」。実行中のノードには出ない |
| 回収の指示の確認 | 取り消せない旨・満たしていない条件・原因（プロセスの pid）・失われるもの（コミット数・未保存・未追跡）・先端（12 桁）が出る。件名の XSS 文字列は、文字として出て、実行されない。確認の前に、指示の要求は出ない |
| 打ち込み（対象のノード ID） | 一致するまで送れない（`S1`・前後の空白・全角・一部は不一致）。無効化を迂回しても、要求が出ない |
| 先端の照合 | 見せたあとで先端が変わると、送っても `tipMismatch` で、確かめ直しの案内（同じ内容の再送は案内しない）。送った `expectTips` は、見せた先端 |
| 確かめ直し | 戻る→もう一度で、新しい先端が出て、通る。`requestId` は新しい。二重クリックでも 1 回。通ったあと、行が「破棄を指示済み」になる |
| 失われるものを調べられない | 理由と cli の案内が出て、打ち込みの欄がなく、送れない |

## 停止の宣言

| 項目 | 期待 |
| --- | --- |
| 出し分け | 停止未完了で `stopDelegated` のノード（c1）だけに「止めたと宣言…」。停止未完了でも直接止めるノード（c2）・停止したノード・実行中のノードには出ない |
| 根拠の XSS | 根拠に入れた `<img onerror>`・`<script>` は、確認に文字として出て、実行されない（`window.__xss` が立たない。確認の中に img・script の要素がない） |
| 確認の表示 | 取り消せない旨と、対象のノード ID が出る。確認の前に、宣言の要求は出ない |
| 打ち込み（対象のノード ID） | 一致するまで送れない（`C1`・前後の空白・全角・一部は不一致）。無効化を迂回しても、要求が出ない |
| 送る値 | params は `{ nodeId, note }` で、note は確認に出した整えた値（前後の空白を削り、連続する空白を 1 つに）と一致。二重クリックでも 1 回 |
| 停止済みのあと | ボタンが消える |

確認の表示: `docs/images/ui-confirm-stopped.png`

## フックの結び付けを外す

`scripts/ui-browser-check.mjs` の `hookUnbind`（実ブラウザ。Chromium）。

| 項目 | 期待 |
| --- | --- |
| 出し分け | 動いている子（a・constructor）だけに「フックの結び付けを外す…」。統合ノード（root・m1）・停止未完了（c1）・停止（s1）には出ない |
| 確認の表示 | 対象のノード ID・目的（「/clear・--resume で session_id が変わって、フックが拒否され続けるとき」）・「次に来たセッションに結び直す」・トークンが漏れた疑いのときの注意が出る。打ち込みの欄はない。確認の前に、要求は出ない |
| XSS | 受信箱の要約の `<img onerror>`・`<script>` は、木・確認に要素として出ず、実行されない（`window.__xss` が立たない） |
| 送る値 | params は `{ nodeId: "a" }`。二重クリックでも 1 回 |
| 結果の文 | 下の 3 通りの通知の全文が `hu.texts` に記録される。確認のたびに requestId は新しい |

`hu.texts` に期待する通知の全文:

1. 「フックの結び付けを外しました（a）。次に来たセッションに結び直します」（1 回目）
2. 「すでに記録済みです（再送。もう一度は外していません）（a）」（daemon が再送として返したとき）
3. 「フックの結び付けはありませんでした（記録だけ残しました）（constructor）」（結び付けがないとき）

## 取り消せない操作の確認待ち

`scripts/ui-browser-check.mjs`（実ブラウザ。Chromium）。確認の口（`createConfirmationGate`）で包んだ窓口に、人間のトークンで `node.purge` を送り、画面で確かめる（結果は `confirmation`）。

| 確かめること | 期待 |
|:--|:--|
| 確認待ちがないとき | 欄は出ない |
| 人間のトークンだけの最終削除 | `confirmationRequired`。実行しない |
| 欄の位置 | スクロールなしで見える位置（ページの上）。入力欄にフォーカス |
| コード | 画面に出ない。番号の先頭は、端末の行と画面で同じ |
| 誤ったコード | `confirmationInvalid` が欄に出て、実行しない |
| 正しいコード（小文字で打つ） | 1 回だけ実行し、欄が消え、通知が出る |
| 5 回目の誤り | 確認待ちは消え、理由（試行の上限）がページ全体の赤い通知に残る |
| 期限切れ | 理由が赤い通知に出る |
| 実行のあとの失敗（`purgeStale`） | 理由が赤い通知に出る。実行は数えない |
| ほかの入力欄で打っている最中に、確認待ちが出る | フォーカスを奪わない。打った文字が残る |

## 使い勝手（#13）

`scripts/ui-browser-check.mjs` の `ux`（実ブラウザ。Chromium。高さ 600 の画面）。

| 確かめること | 期待 |
| --- | --- |
| ページの下の「破棄して回収を指示…」を押す | 確認の欄が画面の中に入り、フォーカスが欄の中にある（`confirmVisible`・`focusInConfirm`） |
| 打ち込ませる ID | 1 回のクリックで全体が選ばれる（`typedValueSelectable`） |
| stopDelegated の子の停止未完了 | 受信箱に「停止の代行依頼」（赤の「失敗」でない）。直接止める子は「失敗」のまま |
| 根に出る、Desktop の子を確かめる依頼 | 「停止の代行依頼」（赤の「失敗」でない） |
| 停止したノードの未解決の項目 | 木の行に「要対応」を出す（人が決めることが残りうる）。アーカイブ済みのノードには出さない |
| 入力欄 | すべて id と name を持ち、id は一意 |
