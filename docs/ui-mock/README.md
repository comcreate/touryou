# 状態画面 モック（Issue #236 第 1 段階・#238）

`touryou ui` で開く状態画面を大きく作り直すための、**静的なモック**です。人が見て直すためのもので、本番のコード（`packages/` 以下）は変えていません。

## 開き方

ブラウザで `docs/ui-mock/index.html` を開きます（ファイルをそのまま開くだけ。サーバーは要りません）。

- 外部の通信・外部のフォントはありません（HTML・CSS・インライン SVG と、ページの中の 2 つの script だけ。1 つは WebGL の背景、もう 1 つは明暗・タブなどのモック用の操作）。
- 左上は、開いているリポジトリ名（ダミー: `comcreate/sample-repo`）だけです。製品名 `touryou` は出しません。ブラウザのタブの題（`<title>`）もリポジトリ名だけで、モックであることは、うしろに「（モック）」と添えて示します（本番では添えない）。
- 上のバーの「◐ 自動」で、OS に合わせる → 明るい → 暗い と切り替わります。OS の設定（`prefers-color-scheme`）にも従います。背景の色も一緒に変わります。
- 画面の組み方は見本（`ref/sample.html`）どおり、上のバー＋3 列（あなたの番・やり取りの図・作業のようす）で、画面全体はスクロールせず、列の中だけスクロールします（900px 以上）。3 列の後ろに、動く全面の背景が透けて見えます。
- 3 列に出ない部品（接続切れ・トークン入力・確認の欄・設定の窓・管理など）は、同じページの下の「部品の見本帳」に並べています（上の歯車を押すと、設定の窓へ移ります）。
- 900〜1279px は、左に「あなたの番」、右に「図（上）＋作業のようす（下）」。1280px 以上は 3 列。899px 以下は 1 列で、下のタブ（出番／図と作業）で切り替えます。
- スマホの幅（400px）は、ブラウザの幅を狭めるか、開発者ツールの端末表示で確かめます。
- 設定の窓の「動きを止める」を入れると、背景がその時点の絵で止まり、線の動きも止まります。OS の「視差効果を減らす」（`prefers-reduced-motion`）でも止まります。
- WebGL が使えないブラウザ（または、開発者ツールで WebGL を切ったとき）は、代わりに静的な SVG の背景が出ます。
- 画面の値はすべてダミーです（実際のトークン・パス・ID は書いていません）。

## 全面の背景（WebGL）

`ref/architect_backgrounds.tsx` の `ModernBlueprintBackground` を、React を使わない素の JS と、全面に固定した `<canvas id="bg-gl">` の WebGL に移しました（`index.html` の `<script id="bg-webgl">`）。

- **シェーダーは見本のまま**です。等角投影の傾き（`tilt`・回転 0.42）、斜めに流れる 2 段の方眼（細・太）、太い方眼の交点の小さな十字、大工・設計道具 6 種（差し金・コンパス・金槌・のこぎり・のみ・鉛筆）の距離関数と色、道具の回転・浮遊・明滅、2 層の光の塵の瞬き、動く環境光、ビネット、紙の粒。違いは、高い精度（`highp`）が使えない端末のために `precision` を分岐したことだけです。
- **画面の大きさ**: 毎回の描画の前に、canvas の CSS の箱（全面に固定）の幅・高さ × `devicePixelRatio`（上限 2。見本と同じ）に canvas を合わせます。`resize` と、`devicePixelRatio` の変化（別の画面へ窓を移したときなど。`matchMedia("(resolution: …dppx)")` で見張る）でも描き直します。
- **明暗**: `html` の `data-theme`（`light`・`dark`・なし＝OS に合わせる）と、OS の `prefers-color-scheme` から決め、シェーダーの `u_isDark` に渡します。`MutationObserver` で `data-theme` の変化を見るので、明暗の切り替えのボタンと結び付いていません。
- **動きを止める**: `html` の `.still`（設定の「動きを止める」）か `prefers-reduced-motion: reduce` のとき、`requestAnimationFrame` を止め、時間をその値で凍らせて 1 枚だけ描きます。止めている間も、明暗・大きさが変わったら 1 枚描き直します。時間は積み上げで持つので、動かし直しても絵が飛びません。最初から止まっているときも道具が見えるよう、時間は 24 秒から始めます。
- **WebGL がないとき**: 既定は、静的な SVG の背景（`.bg`）が見えている状態です。WebGL で最初の 1 枚を描けたときだけ `html` に `.gl` を付け、CSS で SVG を隠します。WebGL のコンテキストが取れない・シェーダーが通らない（理由はコンソールに出す）・コンテキストを失った（`webglcontextlost`）ときは、`.gl` がなく、SVG が出ます。コンテキストが戻ったら（`webglcontextrestored`）、作り直します。
- **別のファイルに出せる書き方**: 背景の script は、ページのほかの script に頼りません。ページとのやり取りは「`canvas#bg-gl` に描く」「`html` の `data-theme`・`.still` と OS の設定を読む」「`html` に `.gl` を付け外しする」の 3 つだけです。本番では、この script を丸ごと `/ui/` の配信物（例 `bg-webgl.js`）にすれば、CSP が `'self'` だけでも動きます（シェーダーは JS の文字列なので、別のファイルは要りません）。

代わりの SVG の背景（前の段階で作ったもの）は、方眼 2 段・交点の十字・道具 6 種の輪郭・光の塵・ビネットを、静止した絵と、ごくゆるい平行移動（120 秒）で描きます。

## 面（グラスモーフィズム）

半透明の面にしたのは、**外の窓**（上のバー・3 列の窓・見本帳の台・下のタブ・設定の窓）と**中の面**（カード・関係図の盤など）の 2 種類だけです。それ以外の部品は不透明で塗りつぶします（下の「不透明の部品」）。

- **ぼかしは二重です。** 窓の中は 1 回、中の面の部分は 2 回ぼけて、中の面がもう一段浮いて見えます。値は CSS 変数に分けてあり、あとで変えられます: 外 `--blur-outer`・中 `--blur-inner`。塗りと同じく、明（`:root`）と暗（`@media (prefers-color-scheme:dark)` の中と `:root[data-theme="dark"]` の 2 か所）で別に定義しています（いまは明 外 `blur(3px)`・中 `blur(6px)`、暗 外 `blur(5px)`・中 `blur(10px)`。どれも `saturate(160%)` を添える）。
- **外の窓**（上のバー・3 列の窓・見本帳の台・スマホの下のタブ・設定の窓）: 窓そのものには `backdrop-filter` を付けず、窓の背面に敷いた疑似要素（`::before`。`position:absolute; inset:0; border-radius:inherit; z-index:-1; pointer-events:none`）に、塗り（`--win`: 明 `rgba(244,241,234,.10)`・暗 `rgba(22,20,18,.20)`）と `--blur-outer` を持たせています。窓本体は `position:relative; isolation:isolate` で、`::before` を自分の後ろに回すだけです。縁は明 `rgba(255,255,255,.45)`・暗 `rgba(255,245,235,.12)`、影は明 `0 4px 16px rgba(0,0,0,.05)`・暗 `0 8px 32px rgba(0,0,0,.35)`（縁と影の値は見本 `ref/sample.html` の `--glass-*` のまま）。
- **中の面**（カード・作業の札・承認の欄・受信箱の項目・確認の欄・凡例の欄・一覧・保管の欄・接続切れの帯・空の表示・作業の内訳・関係図の盤など、`--panel` を使う面）: 薄い塗り（明 `rgba(255,255,255,.20)`・暗 `rgba(22,36,60,.30)`）に `--blur-inner`、細い縁（`--edge`）、上辺の光の線、淡い影。窓の見出し・窓のタブ・窓の下の帯は、窓の一部として塗りなしです。
- **`::before` で二重にする理由**: `backdrop-filter` を持つ要素は、その中の要素にとっての「背景の根」（backdrop root）になり、中の要素でぼかしても、根より後ろ（WebGL の背景）までは届きません。窓そのものにぼかしを付けると、中の面のぼかしが窓の中だけで止まってしまいます。そこで、窓のぼかしを窓の背面の `::before` に移しました。`::before` は窓の子なので、窓は背景の根になりません。中の面は、WebGL の背景と、`::before` がぼかした結果を、もう一度ぼかします。`isolation:isolate` は重なりの文脈を作るだけで、背景の根にはなりません（仕様で背景の根になるのは、`filter`・`opacity` が 1 未満・`mask`・`clip-path`・`backdrop-filter`・`mix-blend-mode`・それらの `will-change` を持つ要素と、根の要素）。
- **背景の根を作らないための決め**: 窓と、中の面の祖先（列の中のスクロールの箱 `.wb` など）には、`filter`・`opacity` が 1 未満・`mask`・`clip-path`・`will-change` を付けていません。`.win` の `overflow:hidden` と角の丸み、`.wb` の `overflow:auto` は、仕様では背景の根になりません。済んだカード・行・図の箱も、`opacity` ではなく文字の色で薄く見せます（図の箱は、箱の中の文字と帯だけに `opacity` を付け、箱そのものは不透明）。
- **入れ子の中の面はぼかしません**: 保管の欄（`.admin`）の中のカードと空の表示などです。外側の中の面がぼかしを持つと、それが背景の根になり、入れ子の面のぼかしは WebGL まで届かないためです（`:is(中の面) :is(中の面)` で `backdrop-filter:none`）。
- **設定の窓**（`dialog.settings`）は、本番では外の窓の外に出る面なので、外の窓と同じ扱いにしています。このモックでは見本帳の台（`.sheet`）の中にありますが、台も `::before` でぼかしているため背景の根にならず、設定の窓のぼかしも WebGL の背景まで届きます（台の中では二重になる）。
- これまでの値の移り変わり: 外 48% の上に中 32%（実効 65〜70%）→ 外 25%（ぼかし 16px）の上に中 6% → 外 15% の上に中は塗りなし → 外 3%・ぼかしなしの上に中 10%・ぼかし 14px → 外 5%・暗 10%・ぼかし 7px の上に中 5%・ぼかしなし → 外は `::before` で 5%・暗 10%・ぼかし 7px、中 5%・ぼかし 7px の二重 → いまの値（利用者が微調整の窓で決めた値。明: 外 10%・ぼかし 3px、中 20%・ぼかし 6px。暗: 外 20%・ぼかし 5px、中 30%・ぼかし 10px）。
- **色で意味を示す部品の塗りはそのまま**: 状態の帯（左の太い線・動いているカードの緑の見出し）、押すボタン（柿・松）、状態の札（chip）、出番の行の柿の地、接続切れの帯など。
- **不透明の部品**: 窓と中の面のほかの部品は、`--panel-solid`（明 `#fbfaf6`・暗 `#0c1424`。明・暗の 3 か所で定義）で塗りつぶします。
  - ボタン: 枠だけのもの（断る・認めない・止める・写す・やめる）、ズーム（＋・−・全体）、図と一覧の切り替え、上のバーの明暗と歯車、「止めた・済んだ子を隠す」など。押せないボタンは、透けさせず、灰の文字と点線の縁で示します。柿・松の押すボタンは、色で意味を示すので、そのままです。
  - 状態の札（chip）: もともと不透明の地（`--grid` と各色の `-soft`）。接続が切れた札（`.chip.lost`）だけ透明だったので、`--panel-solid` にしました。
  - コマンドの欄（`.cmd`。`pnpm test …` など）: 中の面から外し、`--panel-solid` の地に点線の縁。
  - 入力欄（トークン・規則・対象の ID）: もとから `--panel-solid`。
  - 関係図の箱（`.nd .box`）: `--panel-solid`。上辺の光の線（`.hl`）はそのまま。済んだ子の箱は、中の文字と帯だけを薄くします。
  - 線の上の札（`.pill`。「↑ 判断 3 分前」など）と出入口の点（`.pd`）: もとから不透明。
  - 親の右の細いバー（`.bar`）: 前は灰の 45% で透けていたので、それを `--panel-solid` の上に置いた色を、不透明の `--bar-solid`（明 `#aaacad`・暗 `#525b6b`）にしました。
  - 凡例の中の札（`.lg`）: `--panel-solid` の地に細い縁の丸薬の形にしました。
- **窓のタブ**（`.wtab`）と**下のタブ**（`.nb`）は、窓の帯の一部として塗りなしのままです（切り替えの印は、下の線と太字）。
- 受信箱の行（`.inbox li`）は中の面です。いまの行の中には、矢印と文字のほかに札がないので、塗りを足した部品はありません（札を足すときは、上の決めに従って不透明にする）。

## 微調整の窓（モック専用）

面の透明度とぼかしを、画面を見ながら決めるための窓です。**このモックの中だけのもので、本番の状態画面には持ち込みません。**

- **開き方**: 画面の右下の「調整」ボタンを押すと、小さな窓が開きます（スマホの幅では、下のタブの上に出ます）。「閉じる」ボタンか Esc で閉じます。閉じると、焦点は「調整」ボタンに戻ります。
- **変えられる値**: スライダーを動かすと、その場で `:root` の CSS 変数が書き換わります。各スライダーの右に、いまの値が数字で出ます。
  - 外の窓の塗りの濃さ（`--win` のアルファ）: 明・暗を別々に、0〜60%（1% 刻み）
  - 中の面の塗りの濃さ（`--panel` のアルファ）: 明・暗を別々に、0〜60%（1% 刻み）
  - 外の窓のぼかし（`--blur-outer`）: 明・暗を別々に、0〜40px（1px 刻み。`saturate(160%)` はそのまま）
  - 中の面のぼかし（`--blur-inner`）: 明・暗を別々に、0〜40px（1px 刻み。同上）
- **明と暗**: 塗りとぼかしの値は、どちらも明・暗で別々に持ちます（スライダーは、塗り 4 本・ぼかし 4 本の計 8 本）。いま出ている明暗のほうがすぐ効きます（その行が太字になります）。上のバーで明暗を切り替えると、切り替えた先の値が効きます。塗りの色味（RGB）はいまの CSS の値のままで、アルファだけ変わります。
- **既定に戻す**: 書き換えを外して、CSS に書いた値（塗り 外 明 10%・暗 20%、中 明 20%・暗 30%、ぼかし 外 明 3px・暗 5px、中 明 6px・暗 10px）に戻します。残した値も消します。
- **値を写す**: いまの値を、CSS 変数の宣言の文字列（明の `:root` に書く分と、暗の 2 か所に書く分。どちらにも `--win`・`--panel`・`--blur-outer`・`--blur-inner` が入る）にして、クリップボードに写します。写せないとき（ブラウザが許さないときなど）は、窓の中の欄に出すので、選んで写してください。決めた値は、この文字列を `index.html` の 3 か所の定義に書き写して反映します。
- **残し方**: 値はブラウザの `localStorage`（キー `touryou-mock-tune-v2`）に残り、読み込み直しても続きから使えます。ぼかしを明・暗で分けたときに保存の形を変えたので、古いキー `touryou-mock-tune` の値は読まずに消します（前に残した値は、既定の値に戻ります）。`localStorage` が使えないとき（プライベートの窓など）は、残さずに動きます。
- **操作**: キーボードだけで使えます（Tab で移り、スライダーは矢印・Home・End で動かす）。スライダーには、それぞれラベルを付けています。窓そのものは、読みやすさを優先して不透明の面にしています。
- **外し方**: `index.html` の `<style id="tune-css">`、「調整」ボタンと `<section id="tune">`、`<script id="tune-js">` の 3 つを消すと、まるごと外れます（ほかの部品は、この窓に頼っていません）。

## 文字を読みやすくするための決め

- 本文のコントラストは 4.5:1 以上を目標にしています。面を薄くしたので、面全体を濃くする代わりに、**明の文字の色を濃くしました**: 補足 `#51565d` → `#474c53`、藍 `#2a5fa8` → `#24548f`、柿 `#b04a00` → `#974000` → `#903d00`（外の窓をごく薄く（3〜5%）したときに、窓の上の柿の文字が `#974000` では約 4.4:1 と 4.5:1 を割る見込みになったため、もう一段濃くした）、松 `#2c6b44` → `#275f3c`、黄 `#7a5c00` → `#6b5000`。暗の文字の色は変えていません（暗い地の上で十分に高いため）。

## 見本から取り入れたこと

見た目の方針（`ref/sample.html`）:

- **配色の語**: 柿（あなたの出番・答え待ち）・松（動いている）・朱（失敗）・黄（止まっているかも）・藍（上り・リンク・焦点）。明暗それぞれに値を持ち、状態は色だけでなく「▶ ● ✓ ✕ ‖」の記号と文字でも示します。
- **すりガラスの面**: 上の「面（グラスモーフィズム）」の節のとおり。
- **文字**: 本文 15px・行間 1.7。見出しは等幅で字間を広げた小さな札（`01 接続と通知` など）。関係図の札も等幅。
- **カードの形**: 角丸 8〜14px。状態の帯（左の太い線・動いているカードの緑の見出し）。上の状態の札（chip）は丸薬の形。
- **関係図**: 左が親、右が子。親の右に細いバー、線ごとの出入口の点。折れ線の角を丸め、種類ごとの色と、「↑ 判断 3 分前」の札を線の上に置く。新しいほど濃く太く、古いほど薄く細く。送ったが届いていない線は破線を流す。
- **余白とタッチ**: 押せるものは 44px 以上。スマホは 1 列。
- **画面の組み方**: 上のバー＋3 列、列の中だけスクロール、各列に窓の見出しとタブ、スマホは下のタブ 2 つ。
- **答えのボタン**: カードの中の答えのボタンは、横幅いっぱいの大きいボタン（高さ 48px、広いときは横に等分）。

全面の背景（`ref/architect_backgrounds.tsx`）: 上の「全面の背景（WebGL）」の節のとおり、シェーダーをそのまま使っています。

## 取り入れなかったこと

- **React**: 背景は、素の JS と WebGL にした。
- **見本の明暗の切り替えのボタン**（画面の下の「Light Mode」）: このモックの上のバーの明暗の札と、設定の窓の明暗で切り替える。
- **sample.html のオーロラ（canvas のぼかし）**: 全面の背景は architect_backgrounds.tsx を使う指示なので採らない。
- **sample.html の見本用の操作**（接続を切ってみる・案の一覧）と、画面の言語・設定の保存、関係図のドラッグ・ズームの動き: 見た目だけを置いた（ボタンは置いてあるが、押しても何も起きない）。
- **見本の仮の言葉**（注文画面・支払い方法など）は、そのままダミーとして使った。

## 守っていること

- **キーボードの焦点**: 3px の藍の輪郭（`:focus-visible`）。関係図の箱は Tab で届き、焦点で縁が太くなる。「本文へ移る」のリンクあり。窓のタブは左右の矢印・Home・End で移れる。
- **関係図の文字**: 札・箱の文字は図の座標で 12.5〜14px。幅 1440px の中央の窓では、ほぼ等倍（約 1.05 倍）で出る見込み（実機の計測はしていない）。
- **横スクロール**: 本文・窓・カードに `min-width:0`・`minmax(0,1fr)`・`overflow-wrap:anywhere` を入れている。左上のリポジトリ名は、長いときは「…」で切る。幅 375px・400px の実機表示は、このモックの作成時には確かめていない（見る人が確かめる）。
- **動き**: `prefers-reduced-motion` と、設定の「動きを止める」で、背景（WebGL・SVG とも）・接続の丸の呼吸・破線の流れを止める。
- **読み上げ**: 背景の canvas と SVG は `aria-hidden`。状態は文字でも示し、矢印には `aria-label`（上り・下り）、図には `role="group"` とラベル。
- **明暗**: `prefers-color-scheme` と、明暗の手動の切り替え（`data-theme`）の両方。

## 確かめていないこと

このモックを作った作業では、ブラウザで開いて見ることも、スクリーンショットを撮ることもできませんでした。次のことは、見る人が確かめてください。`index.html#theme=dark`（または `#theme=light`）で開くと、その明暗で始まるので、headless のブラウザでスクリーンショットを撮るときに使えます。

- WebGL の背景が描かれ、方眼が流れ、道具が回って浮かび、塵が瞬くこと（シェーダーは見本のままなので、見本と同じ絵になる見込み）。
- 「動きを止める」と OS の「視差効果を減らす」で止まること。WebGL を切ると SVG の背景が出ること。
- 明・暗とも、列の後ろに WebGL の方眼と道具がはっきり見えること。上の表のコントラストの見込みが、実際の画面でも保たれること。
- 明・暗・スマホの幅（375px・400px）で崩れないこと。
- スマホの幅では、画面全体がスクロールし、上のバー（`.top`・貼り付き）と下のタブ（`.nav`・固定）の下を本文が通る。この 2 つは塗りが薄く（明 10%・暗 20%）、ぼかしも明 3px・暗 5px と弱いので、通る本文が透けて、バーの文字が読みにくくなるおそれがある。
- 中の面の部分が、窓の中より一段ぼけて浮いて見えること（ぼかしの二重）。ブラウザによって背景の根の扱いが違うことがあり、特に Safari（`-webkit-backdrop-filter`）では、中の面のぼかしが窓の中で止まって見えることがある。
- 入れ子の中の面（保管の欄の中のカードなど）は、塗り（明 20%・暗 30%）が重なって濃くなる（ぼかしは付けていない）。
- 不透明にした部品（ボタン・凡例の札・コマンドの欄・図の箱など）が、透ける面の上で浮きすぎないか。親の右の細いバーの不透明の色（明 `#aaacad`・暗 `#525b6b`）は、`--panel-solid` の上に置いたと見なした手計算で、透ける盤の上での見え方は確かめていない。
- 微調整の窓のスライダーで、値がその場で変わること。明暗を切り替えると、その明暗の値に変わること。読み込み直しても値が残ること。「値を写す」でクリップボードに写ること（`file://` で開いたときは、ブラウザによって写せないことがある。そのときは窓の中の欄に出る）。

## 次の段階

ブラッシュアップのあと、この見た目になるように、`packages/daemon/src/api/ui-assets.ts` と `packages/daemon/src/ui/*` を直します。直すときの注意（モックでは扱っていないこと）:

- CSP が `'self'` だけを許すため、インラインの `<script>`・`<style>` は置けない。WebGL の背景の script（`#bg-webgl`）は、丸ごと `/ui/` の配信物の別のファイルにする（シェーダーは JS の文字列なので、そのまま入る）。代わりの SVG の背景も、インラインではなく別のファイルにするか、CSS の中で作る形が要る。
- リポジトリ名は、daemon が知っている、開いている木の作業ツリーから出す（モックはダミー）。
- モックの明暗の切り替えは、本番では既存の `theme-light`・`theme-dark` のクラスの仕組みを使う。背景の script が見る `data-theme` は、そのクラスに読み替える。
- 描画は `textContent` と `createElement` だけ（`ui-assets.test.ts` の走査）。
- 微調整の窓（右下の「調整」ボタンと、`<style id="tune-css">`・`<section id="tune">`・`<script id="tune-js">`）は、モック専用です。本番には持ち込みません。本番には、微調整の窓で決めた値だけを、CSS 変数の既定の値として移します。
- `<title>` の「（モック）」は本番では付けず、リポジトリ名だけにします。
