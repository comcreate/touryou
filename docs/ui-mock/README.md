# 状態画面 モック（Issue #236 第 1 段階・#238）

`touryou ui` で開く状態画面を大きく作り直すための、**静的なモック**です。人が見て直すためのもので、本番のコード（`packages/` 以下）は変えていません。

## まず見る所（3 行）

1. `index.html` をブラウザで開き、3 列（あなたの番・やり取りの図・作業のようす）と明暗の切り替えを見る。
2. 上のバーの歯車で設定の窓を開き、その下の「管理（取り消せない操作を含む）…」で管理の窓を見る。
3. 下の「部品の見本帳」で、接続切れ・トークン入力・取り消せない操作の確認などを見る。

## 開き方

ブラウザで `docs/ui-mock/index.html` を開きます（ファイルをそのまま開くだけ。サーバーは要りません）。

- 外部の通信・外部のフォントはありません（HTML・CSS・インライン SVG と、ページの中の 3 つの script だけ。1 つは WebGL の背景（`#bg-webgl`）、1 つは明暗・タブなどのモック用の操作、1 つは微調整の窓用（`#tune-js`））。
- 左上は、開いているリポジトリ名（ダミー: `comcreate/sample-repo`）だけです。製品名 `touryou` は出しません。ブラウザのタブの題（`<title>`）もリポジトリ名だけで、モックであることは、うしろに「（モック）」と添えて示します（本番では添えない）。
- 上のバーの明暗のボタン（アイコンと「自動」）で、OS に合わせる → 明るい → 暗い と切り替わります。OS の設定（`prefers-color-scheme`）にも従います。背景の色も一緒に変わります。
- 画面の組み方は見本（`ref/sample.html`）どおり、上のバー＋3 列（あなたの番・やり取りの図・作業のようす）で、画面全体はスクロールせず、列の中だけスクロールします（900px 以上）。3 列の後ろに、動く全面の背景が透けて見えます。
- 設定と管理は、本番と同じくダイアログで開きます（上のバーの歯車で設定、設定の窓の下の「管理（取り消せない操作を含む）…」で管理。下の「窓（設定・管理のダイアログ）」の節）。ページを下までスクロールしても、ダイアログの中身は並んでいません。
- 3 列に出ない、そのほかの部品（接続切れ・トークン入力・確認の欄など）は、同じページの下の「部品の見本帳」に並べています。見本帳の 05・06 には、設定・管理のダイアログを開くボタンだけを置いています。
- 900〜1279px は、左に「あなたの番」、右に「図（上）＋作業のようす（下）」。1280px 以上は 3 列。899px 以下は 1 列で、下のタブ（出番／図と作業）で切り替えます。
- スマホの幅（400px）は、ブラウザの幅を狭めるか、開発者ツールの端末表示で確かめます。
- 設定の窓の「動きを止める」を入れると、背景がその時点の絵で止まり、線の動きも止まります。OS の「視差効果を減らす」（`prefers-reduced-motion`）でも止まります。
- WebGL が使えないブラウザ（または、開発者ツールで WebGL を切ったとき）は、代わりに静的な SVG の背景が出ます。
- 画面の値はすべてダミーです（実際のトークン・パス・ID は書いていません）。
- `index.html#open=settings`・`#open=admin` で、その窓を開いた状態で始まります。

## 全面の背景（WebGL）

`ref/architect_backgrounds.tsx` の `ModernBlueprintBackground` を、React を使わない素の JS と、全面に固定した `<canvas id="bg-gl">` の WebGL に移しました（`index.html` の `<script id="bg-webgl">`）。

- **シェーダーは見本のまま**です。等角投影の傾き（`tilt`・回転 0.42）、斜めに流れる 2 段の方眼（細・太）、太い方眼の交点の小さな十字、大工・設計道具 6 種（差し金・コンパス・金槌・のこぎり・のみ・鉛筆）の距離関数と色、道具の回転・浮遊・明滅、2 層の光の塵の瞬き、動く環境光、ビネット、紙の粒。違いは、高い精度（`highp`）が使えない端末のために `precision` を分岐したことだけです。
- **画面の大きさ**: 毎回の描画の前に、canvas の CSS の箱（全面に固定）の幅・高さ × `devicePixelRatio`（上限 2。見本と同じ）に canvas を合わせます。`resize` と、`devicePixelRatio` の変化（別の画面へ窓を移したときなど。`matchMedia("(resolution: …dppx)")` で見張る）でも描き直します。
- **明暗**: `html` の `data-theme`（`light`・`dark`・なし＝OS に合わせる）と、OS の `prefers-color-scheme` から決め、シェーダーの `u_isDark` に渡します。`MutationObserver` で `data-theme` の変化を見るので、明暗の切り替えのボタンと結び付いていません。
- **動きを止める**: `html` の `.still`（設定の「動きを止める」）か `prefers-reduced-motion: reduce` のとき、`requestAnimationFrame` を止め、時間をその値で凍らせて 1 枚だけ描きます。止めている間も、明暗・大きさが変わったら 1 枚描き直します。時間は積み上げで持つので、動かし直しても絵が飛びません。最初から止まっているときも道具が見えるよう、時間は 24 秒から始めます。
- **WebGL がないとき**: 既定は、静的な SVG の背景（`.bg`）が見えている状態です。WebGL で最初の 1 枚を描けたときだけ `html` に `.gl` を付け、CSS で SVG を隠します。WebGL のコンテキストが取れない・シェーダーが通らない（理由はコンソールに出す）・コンテキストを失った（`webglcontextlost`）ときは、`.gl` がなく、SVG が出ます。コンテキストが戻ったら（`webglcontextrestored`）、作り直します。
- **別のファイルに出せる書き方**: 背景の script は、ページのほかの script に頼りません。ページとのやり取りは「`canvas#bg-gl` に描く」「`html` の `data-theme`・`.still` と OS の設定を読む」「`html` に `.gl` を付け外しする」の 3 つだけです。本番では、この script を丸ごと `/ui/` の配信物（例 `bg-webgl.js`）にすれば、CSP が `'self'` だけでも動きます（シェーダーは JS の文字列なので、別のファイルは要りません）。

代わりの SVG の背景（前の段階で作ったもの）は、方眼 2 段・交点の十字・道具 6 種の輪郭・光の塵・ビネットを、静止した絵と、ごくゆるい平行移動（120 秒）で描きます。

## 面（グラスモーフィズム）

半透明の面にしたのは、**外の窓**（上のバー・3 列の窓・見本帳の台・下のタブ）と**中の面**（カード・関係図の盤など）の 2 種類と、設定・管理の**ダイアログの窓**（下の「窓（設定・管理のダイアログ）」の節）だけです。それ以外の部品は不透明で塗りつぶします（下の「不透明の部品」）。

- **ぼかしは二重です。** 窓の中は 1 回、中の面の部分は 2 回ぼけて、中の面がもう一段浮いて見えます。値は CSS 変数に分けてあり、あとで変えられます: 外 `--blur-outer`・中 `--blur-inner`。塗りと同じく、明（`:root`）と暗（`@media (prefers-color-scheme:dark)` の中と `:root[data-theme="dark"]` の 2 か所）で別に定義しています（いまは明 外 `blur(3px)`・中 `blur(6px)`、暗 外 `blur(5px)`・中 `blur(10px)`。どれも `saturate(160%)` を添える）。
- **外の窓**（上のバー・3 列の窓・見本帳の台・スマホの下のタブ）: 窓そのものには `backdrop-filter` を付けず、窓の背面に敷いた疑似要素（`::before`。`position:absolute; inset:0; border-radius:inherit; z-index:-1; pointer-events:none`）に、塗り（`--win`: 明 `rgba(244,241,234,.10)`・暗 `rgba(22,20,18,.20)`）と `--blur-outer` を持たせています。窓本体は `position:relative; isolation:isolate` で、`::before` を自分の後ろに回すだけです。縁は明 `rgba(255,255,255,.45)`・暗 `rgba(255,245,235,.12)`、影は明 `0 4px 16px rgba(0,0,0,.05)`・暗 `0 8px 32px rgba(0,0,0,.35)`（縁と影の値は見本 `ref/sample.html` の `--glass-*` のまま）。
- **中の面**（カード・作業の札・承認の欄・受信箱の項目・確認の欄・凡例の欄・一覧・接続切れの帯・空の表示・作業の内訳・関係図の盤など、`--panel` を使う面）: 薄い塗り（明 `rgba(255,255,255,.20)`・暗 `rgba(22,36,60,.30)`）に `--blur-inner`、細い縁（`--edge`）、上辺の光の線、淡い影。窓の見出し・窓のタブ・窓の下の帯は、窓の一部として塗りなしです。
- **`::before` で二重にする理由**: `backdrop-filter` を持つ要素は、その中の要素にとっての「背景の根」（backdrop root）になり、中の要素でぼかしても、根より後ろ（WebGL の背景）までは届きません。窓そのものにぼかしを付けると、中の面のぼかしが窓の中だけで止まってしまいます。そこで、窓のぼかしを窓の背面の `::before` に移しました。`::before` は窓の子なので、窓は背景の根になりません。中の面は、WebGL の背景と、`::before` がぼかした結果を、もう一度ぼかします。`isolation:isolate` は重なりの文脈を作るだけで、背景の根にはなりません（仕様で背景の根になるのは、`filter`・`opacity` が 1 未満・`mask`・`clip-path`・`backdrop-filter`・`mix-blend-mode`・それらの `will-change` を持つ要素と、根の要素）。
- **背景の根を作らないための決め**: 窓と、中の面の祖先（列の中のスクロールの箱 `.wb` など）には、`filter`・`opacity` が 1 未満・`mask`・`clip-path`・`will-change` を付けていません。`.win` の `overflow:hidden` と角の丸み、`.wb` の `overflow:auto` は、仕様では背景の根になりません。済んだカード・行・図の箱も、`opacity` ではなく文字の色で薄く見せます（図の箱は、箱の中の文字と帯だけに `opacity` を付け、箱そのものは不透明）。
- **入れ子の中の面はぼかしません**: 外側の中の面がぼかしを持つと、それが背景の根になり、入れ子の面のぼかしは WebGL まで届かないためです（`:is(中の面) :is(中の面)` で `backdrop-filter:none`）。いまのモックには、入れ子になる中の面はありません（前は管理の欄の中のカードがそうだったが、管理はダイアログに移した）。
- これまでの値の移り変わり: 外 48% の上に中 32%（実効 65〜70%）→ 外 25%（ぼかし 16px）の上に中 6% → 外 15% の上に中は塗りなし → 外 3%・ぼかしなしの上に中 10%・ぼかし 14px → 外 5%・暗 10%・ぼかし 7px の上に中 5%・ぼかしなし → 外は `::before` で 5%・暗 10%・ぼかし 7px、中 5%・ぼかし 7px の二重 → いまの値（利用者が微調整の窓で決めた値。明: 外 10%・ぼかし 3px、中 20%・ぼかし 6px。暗: 外 20%・ぼかし 5px、中 30%・ぼかし 10px）。
- **色で意味を示す部品の塗りはそのまま**: 状態の帯（左の太い線・動いているカードの緑の見出し）、押すボタン（柿・松）、状態の札（chip）、出番の行の柿の地、接続切れの帯など。
- **不透明の部品**: 窓と中の面のほかの部品は、`--panel-solid`（明 `#fbfaf6`・暗 `#0c1424`。明・暗の 3 か所で定義）で塗りつぶします。
  - ボタン: 枠だけのもの（断る・認めない・止める・写す・やめる）、ズーム（＋・−・全体）、図と一覧の切り替え、上のバーの明暗と歯車、「止めた・済んだ子を隠す」など。押せないボタンは、透けさせず、灰の文字と点線の縁で示します。柿・松の押すボタンは、色で意味を示すので、そのままです。
  - 状態の札（chip）: もともと不透明の地（`--grid` と各色の `-soft`）。接続が切れた札（`.chip.lost`）だけ透明だったので、`--panel-solid` にしました。
  - コマンドの欄（`.cmd`。`pnpm test …` など）: 中の面から外し、`--panel-solid` の地に点線の縁。
  - 入力欄（トークン・規則・対象の ID）: もとから `--panel-solid`。
  - 関係図の箱（`.nd .box`）: `--panel-solid`。上辺の光の線（`.hl`）はそのまま。済んだ子の箱は、中の文字と帯だけを薄くします。
  - 線の上の札（`.pill`。「↑ 判断 3 分前」など）と出入口の点（`.pd`）: もとから不透明。
  - 親の右の細いバー（`.bar`）: 前は灰の 45% で透けていたので、それを `--panel-solid` の上に置いた色を、不透明の `--bar-solid`（明 `#aaacad`・暗 `#525b6b`）にしました。
  - 凡例の中の札（`.lg`）: `--panel-solid` の地に細い縁の丸薬の形にしました。
- **窓のタブ**（`.wtab`）と**下のタブ**（`.nb`）は、窓の帯の一部として塗りなしのままです（切り替えの印は、下の線と太字）。
- 受信箱の行（`.inbox li`）は中の面です。いまの行の中には、矢印と文字のほかに札がないので、塗りを足した部品はありません（札を足すときは、上の決めに従って不透明にする）。

## 窓（設定・管理のダイアログ）

設定と管理は、本番の設定の窓（`packages/daemon/src/api/ui-assets.ts` の `dialog#settings`）と同じ動きのダイアログにしました（`packages/daemon/src/ui/*` は関係図と言葉のファイルだけで、窓の動きは `ui-assets.ts` にある）。

- **開き方**: 設定は上のバーの歯車（`#gear`。`aria-haspopup="dialog"`・`aria-controls="settings"`）から開きます。管理は、設定の窓の下の「管理（取り消せない操作を含む）…」（`#to-admin`）から開きます。このボタンを押すと、設定の窓を閉じてから、管理の窓を開きます（ダイアログを重ねない）。見本帳の 05・06 の「設定を開く」「管理を開く」からも開けます。どれも `<dialog>` の `showModal()` で開きます。右の窓の「作業の一覧」の下にあった管理のボタンは外しました。
- **管理の入口の見た目**: 設定の窓の「選んだものは、このブラウザに残ります。」の下に、朱の区切りの線（上辺 2px）を引き、その下に、朱の枠と文字のボタン（`button.danger`）と警告の三角のアイコンを置きます。取り消せない操作の窓を開くボタンであることを、色と形と文言で示します。文言は「管理（取り消せない操作を含む）…」で、管理の窓の見出しも同じ「管理（取り消せない操作を含む）」にそろえています（前は「まれに使う操作」で、戻せない操作があることが伝わらなかった）。
- **窓の下の並び**: 上から、朱の区切りの線と管理のボタン、その下に「閉じる」（窓のいちばん下・右寄せ）の順です。前は「閉じる」が管理のボタンより上、窓の途中に出ていました。
- **幕**: `::backdrop` で背景を覆います。色は本番の値（`rgba(0,0,0,.35)`）。幕の外（3 列・見本帳）は、開いている間は押せず、Tab も届きません（`showModal` の動き）。
- **閉じ方**: 窓の下の「閉じる」ボタン（本番の `#close-settings` に当たる）と、Esc（`<dialog>` の既定の動き）と、窓の外の暗い幕のクリックで閉じます。
  - 幕のクリックは、`dialog` 自身に届いた `click` で、座標（`clientX`・`clientY`）が窓の `getBoundingClientRect()` の外にあるときだけ閉じます（窓の余白のクリックも `dialog` 自身に届くので、座標で見分ける）。
  - 窓の中で押して外で離したとき（文字を選ぶドラッグなど）に閉じないよう、押し始めの `pointerdown` も幕の上だったときだけ閉じます。
  - 幕で閉じたときの焦点は、Esc で閉じたときと同じく、`close` の知らせで開いたボタン（管理なら歯車）に戻します。閉じると、焦点は開いたボタンに戻ります（本番は `close` で歯車に戻す）。設定の窓から開いた管理の窓を閉じたときは、設定の窓はもう閉じているので、焦点は上のバーの歯車に戻ります。戻す先は窓ごとに持ちます（`close` の知らせは後から届くので、設定から管理へ移るときに、設定の `close` で焦点を動かさないようにしている）。`#open=admin` で開いたときも、閉じると歯車に戻ります。
- **焦点**: 開くと、設定は最初の「動きを止める」に、管理は窓の見出し（`tabindex="-1"`）に焦点が移ります。Tab・Shift+Tab は窓の中を回ります。回る相手は、本番と同じ選び方（押せる `input`・`select`・`button`。ラジオは選ばれているものだけ）です。
- **見た目**: 窓そのものをグラスモーフィズムにしています。ダイアログは最上位の層（top layer）に出て、幕の上にあり、外の窓の `::before` の決めは使いません（窓の高さが画面を超えると窓の中がスクロールするので、`::before` だと塗りがずれる）。窓そのものに、塗り `--dlg`（明 `rgba(244,241,234,.60)`・暗 `rgba(22,20,18,.60)`）と、ぼかし `--blur-dlg`（明・暗とも `blur(16px) saturate(160%)`）を持たせています。外の窓より濃く、ぼかしも強いのは、窓の後ろに 3 列の文字があり、それが透けて本文が読みにくくならないようにするためです。縁と影は外の窓と同じ。
- **中の部品は不透明**: 窓の中のカード・空の表示は、中の面の塗りではなく `--panel-solid` で塗りつぶし、ぼかしを付けません（窓が `backdrop-filter` を持つので、中でぼかしても窓の中で止まるため）。ボタン・入力欄・状態の札は、ほかの場所と同じく不透明です。枠（`fieldset`）は線だけです。
- **管理の窓**: 取り消せない操作が多いので、縁を朱（2px）にし、見出しも朱にしています。**本番では、管理はダイアログではなく、画面の下の `<details class="admin">` です。** このモックでは、指示によりダイアログにしました。本番に移すときは、管理もダイアログにするかを決めます。
- **設定の窓の幅と高さ**: 幅の上限を置かず、画面に対して左右 48px の余白だけを持つ形です（幅 `calc(100vw - 96px)`。640px 以下では余白 16px で、幅 `calc(100vw - 32px)`）。高さは中身なりで、上下にも 48px（640px 以下は 16px）の余白が残るところで止めます（`max-height: calc(100dvh - 96px)`。640px 以下は `calc(100dvh - 32px)`）。上下左右の中央に置きます（`<dialog>` の既定の `margin:auto`）。
  - 経緯: 前は 30rem で、広い画面では画面の幅の 3 割ほどしかなく、文が細かく折り返されて窓の中のスクロールが長かった。41b004a で `min(52rem, …)` にし、利用者の指摘でさらに上限をなくした。本番の設定の窓は 28rem。

  - 中身が上限の高さを超えると、窓の中がスクロールします。管理の入口と「閉じる」は、中身のいちばん下に続けて出ます。
  - `<dialog>` の既定の `max-width`・`max-height`（`calc(100% - 6px - 2em)`）より大きくするため、`max-width`・`max-height` も書いています。

- **狭い画面（640px 以下）**: 前のまま 1 列です。中央寄せ（`margin:auto`）をやめ、窓を左上から 16px の位置に置き、幅を `calc(100vw - 32px)` にしています。幅 390px の撮影で、設定の窓の右が切れて見えたので、この形にしました。その後、切れて見えた原因は、headless のブラウザの表示の幅が最小 500px になるためで、モックのせいではないと分かりました（撮影した親が確かめた）。この形は、レビューを通ったので、そのまま残しています。設定の窓は高さも `calc(100dvh - 32px)` なので、左上から 16px に置くと、上下左右とも 16px で、中央と同じ位置になります。
- **確かめ用**: `index.html#open=settings`（または `#open=admin`）で開くと、その窓を開いた状態で始まります。`#theme=dark&open=settings` のように明暗と並べられます。

## アイコン

ボタンの一部に、文字に添えてアイコンを付けました。どれもインラインの SVG で、外部のフォント・画像は使いません（本番の CSP の `img-src 'none'`・`'self'` だけの中でも作れる形）。

- **付けたボタン**: 上のバーの歯車（設定）・明暗の切り替え、設定の窓の「設定を読み込み直す」・下の「管理（取り消せない操作を含む）…」、コマンドを写す「写す」（左の窓の答えのカードと、右の窓の作業のカード）。
- **形**: 歯車（丸と 8 つの歯と中の丸）、明暗（自動＝半分塗った丸・明＝太陽・暗＝月）、読み込み直す（丸い矢印）、管理（警告の三角）、写す（重ねた 2 枚の四角）。
- **書き方**: `<svg class="ic" viewBox="0 0 24 24" aria-hidden="true" focusable="false">` の中に `path` だけ。`d` は命令 `M`・`L`・`A`・`C`・`Z` だけで書き、`H`・`V`・`circle`・`use` は使っていません（本番の `packages/daemon/src/ui/svg-el.ts` の許可リストの形に寄せた。本番で svg-el.ts から作るなら、クラス名 `ic` などを許可リストに足す必要がある）。
- **線と大きさ**: `fill:none; stroke:currentColor; stroke-width:2`（丸い端と角）。大きさは文字の高さにそろえて `1.15em`。ボタンは `.ib`（`inline-flex`・間 6px）で、アイコンと文字を中央でそろえます。半分塗った丸の塗りの部分だけ、`fill:currentColor` です（`.ic .f`）。

- **明暗のボタンのアイコン**: 3 つのアイコンをボタンの中に置き、JS がボタンの `data-cur`（`auto`・`light`・`dark`）を書き換え、CSS がそれに合うものだけを出します。文字は名前（`#theme-name`）だけを書き換えます。
- **歯車**: 前は直径約 34px の丸の中に、約 8px の文字「⚙」が出ているだけで、何のボタンか分かりにくかったので、20px の SVG の歯車にし、押せる範囲を 44px 四方（丸）にしました（上のバーの高さ 48px に収まる）。歯は、太さ 4 で端を四角（`stroke-linecap:butt`）にした線です。丸い端だと、隣の明暗のボタンの「太陽」（丸い端の光の線）と似て見えるためです。歯車も `.ib` で、文字の基線でなく、ボタンの縦の中央にそろえます。
- **上のバーの 2 つのボタンの縁**: 明暗と歯車の縁は、`--rule`（暗では `#2a3850` で背景に沈む）でなく、`--ink2`（明 `#474c53`・暗 `#a7b2c2`）の 1.5px にして、明・暗の両方で輪郭を見せます。押す前に触れたときは `--accent` になります。

## 線の流星と枠の光（既定は「まとめ」）

lightswind の animated-meteors-link（曲線の上を流星の尾が流れ、終点で火花が出る表現）を参考に、関係図の線とノードに当てはめる形を、独自に作って置きました。コンポーネントのコードは使っていません（ページにはソースが載っておらず、親が取ったページの説明と props の一覧だけを手がかりにした）。

前は案 A・B・C を 1 つずつ選んで比べる試作（既定は切）でした。利用者が 3 案を見て「3 つともよいので、条件しだいで、上りも下りも枠も光ってよい」と決めたので、**3 案を 1 つの既定の表現（まとめ）にまとめました。**

- **まとめ（既定）**: 条件ごとに出し分け、強さに差をつけます。
  - 上り（子から親への報告）で、あなたの番になる線（橙の「↑ 判断」と朱の「↑ 失敗」）: 案 B の流星と火花。いちばん強く出します（頭の太さ 6・光 2 重・白い芯・尾 45%・1.2 秒）。火花は左の出入口（親の右の細いバー）に当たって、右へ跳ね返ります。2 本は半周期ずらします。
  - 下り（親から子への頼み）で、まだ届いていない線（緑の破線の「↓ 頼み 30 分前」）: 案 A の流星を、ひかえめに出します（頭の太さ 4・光 1 重・芯 1.6・尾 30%・1.8 秒で遅く）。火花は出しません。
  - 答え待ち（橙・支払い方法の画面）と失敗（朱・ありがとうの画面）の箱の縁: 案 C の光を、ひかえめに出します（太さ 2 → 3・光 1px → 5px・1.6 秒で往復）。
  - それ以外の線（届いた頼み・済んだ報告・進み）は流しません。
  - 流す本数の上限: 上り 3 本・下り 2 本です。超えた線は、JS が線の `g` に `.mt-cap` を付けて出しません。モックは図の中の順で選びます（本番は新しい順に選ぶ）。モックの図には上り 2 本・下り 1 本しかないので、上限に当たる線はありません。
  - うるささ: 同時に動くのは、強い上りの流星 2 本と火花 2 か所、弱い下りの流星 1 本、ひかえめな縁の光 2 つです。うるさくないかは、ブラウザでは確かめていません（撮影で見てもらう）。
- **比べる用の選び**: 微調整の窓の「線の流星と枠の光」のラジオ（まとめ（既定）・案 A だけ・案 B だけ・案 C だけ・切）か、`index.html#meteor=all`（`a`・`b`・`c`・`off`）で切り替えます。選びは残しません。1 つだけのときは、前の試作と同じ強さです。
  - 案 A だけ: 届いていない線（破線）に、親から子へ流す。右の箱（確認メール）の縁で、上りより弱い火花が左へ跳ね返る。
  - 案 B だけ: あなたの番に向かう上りの線に、子から親へ流す。
  - 案 C だけ: 線は流さず、答え待ち・失敗の箱の縁を、太さ（2 → 5）と光（`drop-shadow` 2px → 6px＋14px の 2 重）を 1 秒で往復させて脈打たせる。
  - 作り方: まとめのときは、`html` に `.mt-all` と `.mt-a`・`.mt-b`・`.mt-c` をすべて付け、強さの差は `.mt-all` の CSS で付けます。1 つだけのときは、そのクラスだけです。
- **関係図の上の 1 行**: 切のほかは、関係図の窓の上の端（見出しのすぐ下）に、いまの選びの短い説明を 1 行で出します（`#mt-note`。`role="status"`）。まとめのときは、それぞれの意味の短い凡例です（「まとめ：強い流星と火花＝あなたの番／弱い流星＝まだ届かない頼み／縁の光＝答え待ち・失敗」。中央の窓で 1 行に収まるよう、約 40 字にした。詳しい意味は凡例に書く）。1 つだけのときは、前と同じく、どこを見ればよいかです。動きを止めているときは、うしろに「（動きを止めているので出ません）」と添えます。
- **凡例（線の見方）**: 次の 4 つを足しました。
  - 「強い流星と火花：あなたの番になる知らせ（判断・失敗）」（橙。頭の白い短い光る線）
  - 「弱い流星：まだ届いていない頼み」（緑。細く光なし）
  - 「縁の光：答え待ち・失敗の子」（朱。光る縁の小さな四角）
  - 「流星と光は、『動きを止める』と OS の『視差効果を減らす』では出ません」
  - 見本の線は、HTML の `span` に CSS の `linear-gradient` と `box-shadow` で描いています（SVG は使っていない）。
- **明・暗で比べる**: 上のバーの明暗のボタンで切り替えるか、`#meteor=b&theme=dark`・`#meteor=b&theme=light` のように、アドレスで選びと明暗を並べて開きます。同じタブで `#` のうしろだけを書き換えたときも、`hashchange` で明暗と選びを合わせ直します（ページは読み込み直されないため）。流星と枠の光は、線や箱の色（`--c`・`--g`。明・暗で別の値）で描き、流星の頭には白い芯を重ねます。火花は、熱さの色（`--sk1`〜`--sk3`・`--sk-fl`・`--sk-glow`。明・暗で別の値）から、最後に線の色（`--c`）へ冷めます。
- **明の収録に写らなかった理由と直し**: 032cce5 の流星は、頭が太さ 3・尾が太さ 2 で、線と同じ色でした。案 B の判断の線は太さ 2.8 なので、頭も尾も同じ色の線に溶けて、ほとんど見分けられなかったと見ています（DOM と CSS を読んだ範囲では、`#meteor=` で `html` にクラスが付き、`.ma`・`.mb` の path が出る決めに誤りは見つからなかった。ブラウザでは確かめていない）。そこで、頭を太さ 6 にし、中に白い芯（`.mhc`。太さ 2.6・長さ 6）を重ねて、明るさで線と分けました。尾も太さ 5 にして、線からはみ出すようにしました。
- **強さ（比べて見分けられるように、前より強めた）**: 流星の頭は長さ 10・太さ 6（図の座標。窓の幅により 4〜6px 前後）で、`drop-shadow(0 0 3px)` と `drop-shadow(0 0 8px)` の 2 重で光らせ、白い芯を重ねる。尾は長さ 30・太さ 5・45% の濃さ。周期は 1.2 秒で、破線の 1 周期を 62 にしたので、1 本の線に流星が 1〜2 つ同時に流れる（端から端まで約 1.9 秒）。まとめのときの下りは、これより弱く遅い（上の「まとめ」）。
- **始まりの位相**: 読み込んだ直後の 1 枚に違いが写るよう、流星は 1.04 秒ぶん進めて始めます（`animation-delay:-1.04s`。周期の 87% で、頭が当たってから 0.08 秒。最初の 1 枚に、流星 2 つと、飛んでいる途中の火花の筋が入る）。火花は、流星より 0.96 秒遅らせた `-0.08s` です。2 本目の上りの線は、さらに半周期ずらします（流星 `-1.64s`・火花 `-0.68s`）。案 C は、光の強い側から始めます（`-1s`。まとめのときは `-1.6s`）。
- **流星の作り方**: 線と同じ道の `path` を重ね、`pathLength="100"` で長さを 100 と見なす（線ごとに長さを測る JS が要らない）。`stroke-dasharray`（頭 `10 52`、芯 `6 56`、尾 `30 32`。どれも 1 周期 62）の破線を、`stroke-dashoffset` を CSS の `@keyframes` で 1 周期ぶん減らして動かす。頭の前の端が時間の 8 割で道の終わりに着くように始まりの位置（83.6）を決め、芯は前の端を頭にそろえるため 4 だけ小さい値（79.6）から、尾は 20 だけ大きい値（103.6）から動かす。値はどれも正（古いブラウザで負の `stroke-dashoffset` が効かないことを避ける）。上りは、道を逆向きに書いた `path` を重ねる。色は線の種類の色（`--c`）。
- **火花の作り方（光の筋）**: 前の「ぼけた粒が飛び散る」形は、利用者から「壁に当たった光が、まわりに飛び散る」ように、と指摘がありました（たとえは、高温に熱した鉄粉を鉄板に落としたような火花）。そこで、当たった点の閃光と、跳ね返る短く細い光の筋に作り直しました。
  - 置き場所: `g.msp` を、SVG の `transform` 属性で当たった点へ動かします。上りは、左の出入口の帯（x 147〜153。四角い印は 153.5 まで）の手前の (155, 124) と (155, 232)。下りは、右の箱（確認メール。x 412 から）の縁の手前の (410, 147) で、`scale(-1 1)` で左右を返します。中の形は、当たった点を `0 0` とした座標で書き、上りの 2 か所は同じ形です。
  - 向き: 流星の来た向きへ跳ね返します。右から左へ流れる上りは右側へ、左から右へ流れる下りは左側へ。範囲は、当たった面の手前の ±70° の扇です（上りの筋は −68°〜64°）。真後ろに近いほど本数を多く（±15° の中に 16 本のうち 6 本）、道を長く（真後ろの 40 から、端の 18 まで）しました。線分の長さは道の長さに対する割合なので、道が短いと線分も短くなり、点（粒）に見えてしまいます。そのため、端の道の最短を 18 にしています。
  - 閃光（`path.fl`。半径 4 の円を `A` の命令で書く）: 当たった瞬間（火花の周期の 0%）に 1.4 倍の大きさで出て、4% で元の大きさ、12%（約 0.14 秒）で 0.3 倍に縮んで消えます（`@keyframes mt-fl`）。塗りは、暗は白、明は濃い黄（`--sk-fl`）。明るい面の上でも輪郭が出るよう、橙（`--sk-glow`）の細い縁（太さ 0.8）を付けます。
  - 筋（`path.sk`。当たった点から外へ向かう直線。`pathLength="100"`）: 破線の 1 つの線分を、`stroke-dasharray`（線分の長さ）と `stroke-dashoffset`（線分の位置）で動かします。生まれたときは長さ 1 の点で、6% で長さ 20 へ一気に伸び、飛びながら長さ 22 → 14 → 4、太さ 1.5 → 1.2 → 0.9 → 0.4 と細く短くなって、道の 96 のところで消えます。線分の始まりは、道の 0 → 8 → 44 → 74 → 96 と進むので、初めが速く、だんだん遅くなります。線の端は `butt`（丸くしない。丸い端だと短い線分が点に見えるため）。`stroke-dashoffset` は、流星と同じく正の値だけで書きます。破線の 1 周期は（線分 ＋ 200）なので、線分の始まりを b にする値は（線分 ＋ 200 − b）です（例: 6% は 20 ＋ 200 − 8 ＝ 212）。`transform: translate()` で、終わりに下へ 2〜5 垂れます（重力）。
  - 色: 熱い順に `--sk1` → `--sk2` → `--sk3` → 線の色（`--c`）と冷めます。暗は白 → 黄（`#ffe27a`）→ 橙（`#ff9437`）→ 線の色。明は、白や黄の筋が明るい背景に溶けて見えないので、芯を濃い色寄りにし、焦げ茶（`#4a1d00`）→ 暗い黄（`#8a5800`）→ 橙（`#c2410c`）→ 線の色にしました。
  - 寿命と速さ: 寿命は 3 種で、`.sk` が 0.6 秒（`mt-sk1`）、`.sk2` が 0.45 秒（`mt-sk2`）、`.sk3` が 0.3 秒（`mt-sk3`）。3 つは同じ形の動きを、時間だけ縮めたものです。道の長さ（18〜40）と組み合わせるので、筋ごとに長さと速さがばらばらになります（真後ろに近い長い筋に短い寿命を多く当て、速く飛ばす）。
  - 芯の光: `g.msp` に `drop-shadow` を 2 重（1px と 3px。暗は橙寄りの黄、明は橙）にかけ、筋と閃光のまわりを弱く光らせます。
  - 流星との合わせ: 火花の周期も 1.2 秒で、流星の頭が道の終わりに着く時（流星の周期の 80%）を、火花の 0% にします。そのため、火花の `animation-delay` は、流星より 0.96 秒遅らせた値です（下の「始まりの位相」）。
  - 下り（`.weak`）は、上りより弱くしています。筋は 10 本（指示の目安 12〜20 より少ないのは、弱くするため）、道は上りの 7 割ほど（15〜28）、閃光は半径 3、全体を 7 割の濃さ。
  - 本番の CSP の中で作れる形: SVG の `g`（`transform` 属性）と `path`（`d` は `M`・`L`・`A`・`Z` だけ。`pathLength`）と `class` と、配信する CSS の `@keyframes`・変数だけです。`style` 属性・グラデーション・JS の動きは使っていません。`circle`・`line` は使っていないので、タグは本番の許可リストのままで足ります。本番で使うには、`svg-el.ts` の許可リストに、属性 `transform`（または、`g` を動かさず、当たった点を足した座標で `d` を書く）と `pathLength`、クラス名（`msp`・`weak`・`fl`・`sk`・`sk2`・`sk3` など）を足す必要があります。
  - 動きを止める設定と `prefers-reduced-motion` では出しません（`g.msp` を `display:none`）。
  - まとめのときは、上りの当たる点（左の出入口）だけに出し、下りの当たる点（右の箱の縁）には出しません（下りの火花は、案 A だけのときに出る）。
- **本番にある彗星との違い**: 本番には、送ったがまだ届いていない線（`g-sent`）だけに走る「彗星」がすでにあります（`packages/daemon/src/ui/graph-entry.ts` の `cometOf`、CSS は `ui-assets.ts` の `.comet`・`.comet-win`）。本番は、線と同じ `d` の重ね線に `mask` をかけ、mask の中の窓（`linearGradient` で頭が明るく尾が薄い `rect`）を CSS の `translateX` で横へ動かします。動かす向きは横だけで、線の縦の部分は窓の幅の中で一度に光ります。このモックの破線のやり方は、道の形どおりに進みます（縦の部分も順に進む）が、尾は 2 本の濃淡で、本番の mask ほどなめらかには薄れません。本番で使うには、`svg-el.ts` の許可リストに `pathLength` を足し、`d` は `H`・`V` を使わない形（本番は `M`・`L`・`C`・`Q`・`A`・`Z` だけ）にします。
- **動きを止めるとき**: 「動きを止める」と `prefers-reduced-motion` で、ほかの動きと同じく `animation` が切れ、流星と火花は出さない（`display:none`。破線が周期で並ぶので、`animation` を切るだけだと線の上に流星が止まって見えるため）。枠の光も出さず、縁はふだんの太さ 2・光なしに戻す（前の案 C は、弱い光のまま止まっていた。「すべて止める（出さない）」の指示で変えた）。触れたときと焦点が来たときの縁の太さ 3 は、止めていても残す。線の意味は、もとの線の色・破線・札の文字で示しているので、動きがなくても失われない。

## 微調整の窓（モック専用）

面の透明度とぼかしを、画面を見ながら決めるための窓です。**このモックの中だけのもので、本番の状態画面には持ち込みません。**

- **開き方**: 画面の右下の「調整」ボタンを押すと、小さな窓が開きます（スマホの幅では、下のタブの上に出ます）。「閉じる」ボタンか Esc で閉じます。閉じると、焦点は「調整」ボタンに戻ります。
- **変えられる値**: スライダーを動かすと、その場で `:root` の CSS 変数が書き換わります。各スライダーの右に、いまの値が数字で出ます。
  - 外の窓の塗りの濃さ（`--win` のアルファ）: 明・暗を別々に、0〜60%（1% 刻み）
  - 中の面の塗りの濃さ（`--panel` のアルファ）: 明・暗を別々に、0〜60%（1% 刻み）
  - 外の窓のぼかし（`--blur-outer`）: 明・暗を別々に、0〜40px（1px 刻み。`saturate(160%)` はそのまま）
  - 中の面のぼかし（`--blur-inner`）: 明・暗を別々に、0〜40px（1px 刻み。同上）
- **明と暗**: 塗りとぼかしの値は、どちらも明・暗で別々に持ちます（スライダーは、塗り 4 本・ぼかし 4 本の計 8 本）。いま出ている明暗のほうがすぐ効きます（その行が太字になります）。上のバーで明暗を切り替えると、切り替えた先の値が効きます。塗りの色味（RGB）はいまの CSS の値のままで、アルファだけ変わります。
- **既定に戻す**: 書き換えを外して、CSS に書いた値（塗り 外 明 10%・暗 20%、中 明 20%・暗 30%、ぼかし 外 明 3px・暗 5px、中 明 6px・暗 10px）に戻します。残した値も消します。
- **値を写す**: いまの値を、CSS 変数の宣言の文字列（明の `:root` に書く分と、暗の 2 か所に書く分。どちらにも `--win`・`--panel`・`--blur-outer`・`--blur-inner` が入る）にして、クリップボードに写します。写せないとき（ブラウザが許さないときなど）は、窓の中の欄に出すので、選んで写してください。決めた値は、この文字列を `index.html` の 3 か所の定義に書き写して反映します。
- **残し方**: 値はブラウザの `localStorage`（キー `touryou-mock-tune-v2`）に残り、読み込み直しても続きから使えます。ぼかしを明・暗で分けたときに保存の形を変えたので、古いキー `touryou-mock-tune` の値は読まずに消します（前に残した値は、既定の値に戻ります）。`localStorage` が使えないとき（プライベートの窓など）は、残さずに動きます。
- **線の流星と枠の光**: 窓の下のほうに、上の「線の流星と枠の光」の選び（まとめ（既定）・案 A だけ・案 B だけ・案 C だけ・切）のラジオがあります（面の値とは別で、残しません。「既定に戻す」「値を写す」には入らない）。
- **操作**: キーボードだけで使えます（Tab で移り、スライダーは矢印・Home・End で動かす）。スライダーには、それぞれラベルを付けています。窓そのものは、読みやすさを優先して不透明の面にしています。
- **外し方**: `index.html` の `<style id="tune-css">`、「調整」ボタンと `<section id="tune">`、`<script id="tune-js">` の 3 つを消すと、まるごと外れます（ほかの部品は、この窓に頼っていません）。

## 確かめていないこと

このモックを作った作業では、ブラウザで開いて見ることも、スクリーンショットを撮ることもできませんでした。次のことは、見る人が確かめてください。`index.html#theme=dark`（または `#theme=light`）で開くと、その明暗で始まるので、headless のブラウザでスクリーンショットを撮るときに使えます。

- WebGL の背景が描かれ、方眼が流れ、道具が回って浮かび、塵が瞬くこと（シェーダーは見本のままなので、見本と同じ絵になる見込み）。
- 「動きを止める」と OS の「視差効果を減らす」で止まること。WebGL を切ると SVG の背景が出ること。
- 明・暗とも、列の後ろに WebGL の方眼と道具がはっきり見えること。上の表のコントラストの見込みが、実際の画面でも保たれること。
- 明・暗・スマホの幅（375px・400px）で崩れないこと。
- スマホの幅では、画面全体がスクロールし、上のバー（`.top`・貼り付き）と下のタブ（`.nav`・固定）の下を本文が通る。この 2 つは塗りが薄く（明 10%・暗 20%）、ぼかしも明 3px・暗 5px と弱いので、通る本文が透けて、バーの文字が読みにくくなるおそれがある。
- 中の面の部分が、窓の中より一段ぼけて浮いて見えること（ぼかしの二重）。ブラウザによって背景の根の扱いが違うことがあり、特に Safari（`-webkit-backdrop-filter`）では、中の面のぼかしが窓の中で止まって見えることがある。
- 設定の窓の下の「管理（取り消せない操作を含む）…」を押すと、設定の窓が閉じて管理の窓が開き、管理を閉じると焦点が歯車に戻ること。上のバーの歯車が、明・暗の両方で、歯車の形と縁がはっきり見えること。アイコンが文字の高さにそろい、文字と縦の中央がそろうこと。
- 設定・管理のダイアログが、歯車・「管理（取り消せない操作を含む）…」から開き、幕が背景を覆うこと。「閉じる」と Esc と幕のクリックで閉じ（窓の中で押して外で離したときは閉じない）、焦点が開いたボタンに戻ること。Tab・Shift+Tab が窓の中を回ること。窓の後ろの幕と 3 列がぼけて透け、窓の文字が読めること（塗り 60%・ぼかし 16px の上の補足の文字は、明で約 5.5:1、暗で約 8:1 の見込み。手計算で、実機では確かめていない）。スマホの幅で、窓が画面に収まり、窓の中がスクロールすること。設定の窓が、画面から左右 48px（640px 以下は 16px）の余白で中央に出て、高さが中身なり（1920×1080 で 3 列の下と管理のボタンのあいだが空きすぎない）になり、高い中身でも上下 48px（640px 以下は 16px）の余白で止まること。幅 1020〜1499px でアクセシビリティと言語が 2 列・子の権限の規則が全幅、1500px 以上で 3 列になり、文の 1 行が 31〜40 字ほどに収まること。1019px と 1020px、1499px と 1500px の境で崩れないこと。中身が窓の高さを超える低い画面で、窓の中がスクロールし、下の「閉じる」まで届くこと。
- 不透明にした部品（ボタン・凡例の札・コマンドの欄・図の箱など）が、透ける面の上で浮きすぎないか。親の右の細いバーの不透明の色（明 `#aaacad`・暗 `#525b6b`）は、`--panel-solid` の上に置いたと見なした手計算で、透ける盤の上での見え方は確かめていない。
- 実機のスマホ（幅 390px 前後）で、設定・管理の窓が画面の中に収まること。headless のブラウザは表示の幅が最小 500px になるので、それより狭い幅は、実機か開発者ツールの端末表示で見る。
- 線の流星と枠の光の「まとめ」（既定。`#meteor=all`。明暗は `&theme=dark`・`&theme=light`）で、3 つを同時に出してもうるさくないこと。上りの流星と火花がいちばん目立ち、下りの流星と枠の光がひかえめに見えること。関係図の上の 1 行と凡例で、それぞれの意味が分かること。
- 火花が、当たった点の閃光と、跳ね返る短く細い光の筋に見えること（高温の鉄粉を鉄板に落としたように見えるか）。筋が、白（明は焦げ茶）→ 黄 → 橙 → 線の色と冷め、細く短くなって少し垂れて消えるように見えること。明でも筋と閃光が見えること。端の短い筋（道 18 前後、下りは 15）が、点（粒）ではなく筋に見えること。上りの火花が左の出入口の帯の右へ、下りの火花が箱の縁の左へ跳ね返ること。Safari で、`@keyframes` の中の `stroke-dasharray`・`stroke`（`var()`）の移り変わりと、`transform` 属性のある `g` の中の `path` の CSS の `transform` が効くこと。
- 強めた光が、線の札（「↑ 判断 3 分前」など）の文字を読みにくくしないこと。Safari で `pathLength` と `transform-box` が効くこと。動きを止めると、流星・火花・枠の光がどれも見えなくなること。
- 微調整の窓のスライダーで、値がその場で変わること。明暗を切り替えると、その明暗の値に変わること。読み込み直しても値が残ること。「値を写す」でクリップボードに写ること（`file://` で開いたときは、ブラウザによって写せないことがある。そのときは窓の中の欄に出る）。

## 次の段階

ブラッシュアップのあと、この見た目になるように、`packages/daemon/src/api/ui-assets.ts` と `packages/daemon/src/ui/*` を直します。直すときの注意（モックでは扱っていないこと）:

- CSP が `'self'` だけを許すため、インラインの `<script>`・`<style>` は置けない。WebGL の背景の script（`#bg-webgl`）は、丸ごと `/ui/` の配信物の別のファイルにする（シェーダーは JS の文字列なので、そのまま入る）。代わりの SVG の背景も、インラインではなく別のファイルにするか、CSS の中で作る形が要る。
- リポジトリ名は、daemon が知っている、開いている木の作業ツリーから出す（モックはダミー）。
- モックの明暗の切り替えは、本番では既存の `theme-light`・`theme-dark` のクラスの仕組みを使う。背景の script が見る `data-theme` は、そのクラスに読み替える。
- 描画は `textContent` と `createElement` だけ（`ui-assets.test.ts` の走査）。
- 微調整の窓（右下の「調整」ボタンと、`<style id="tune-css">`・`<section id="tune">`・`<script id="tune-js">`）は、モック専用です。本番には持ち込みません。本番には、微調整の窓で決めた値だけを、CSS 変数の既定の値として移します。
- `<title>` の「（モック）」は本番では付けず、リポジトリ名だけにします。
- 本番の設定の窓は、いまの開き方・閉じ方・焦点の動きのまま、見た目（`--dlg`・`--blur-dlg`、中の部品の不透明）と、幅と高さ（本番の 28rem をやめ、画面から上下左右 48px の余白。640px 以下は 16px）と中の組み方（画面の幅で 1〜3 列の `.set-cols`。境は 1020px・1500px。`.policy-groups`、文の `max-width:40em`）を移します。管理をダイアログにするなら、取り消せない操作の確認の欄（本番の `#confirm`。いまは `main` の中の欄）も、管理の窓の中に出す形が要ります（幕の下に確認の欄が出ると、押せないため）。管理の入口は、本番でも設定の窓の下（「閉じる」の上）に置き、文言は「管理（取り消せない操作を含む）」にそろえ、設定を閉じてから管理を開き、管理を閉じたら歯車へ焦点を戻す。幕のクリックで閉じる動き（押し始めと離した所の両方が幕の上のときだけ）は、本番の設定の窓にはまだないので、移すときに足す。
- 線の流星と枠の光の「まとめ」を本番に移すときは、下りの流星（まだ届いていない線）が、本番にすでにある彗星（`g-sent` の `.comet`）と同じ線に当たるので、どちらか 1 つにする（彗星を、まとめの弱い流星の強さに合わせるか、流星に置き換える）。上りの流星・火花の筋・枠の光は、本番にはまだない。流す本数の上限（上り 3 本・下り 2 本）は、新しい順に選ぶ。`svg-el.ts` の許可リストに、`pathLength`・`transform`（火花の `g` を当たった点へ動かす。足さないなら、当たった点を足した座標で `d` を書く）と、使うクラス名を足す（火花はタグ `path` と `g` だけなので、タグは足さなくてよい）。
- アイコンの SVG を本番で `svg-el.ts` から作るなら、クラス名（`ic`・`f`・`i-auto` など）と `aria-hidden`・`focusable`・`stroke-width` を許可リストに足すか、アイコンを配信する CSS・HTML の側に置くかを決める。
