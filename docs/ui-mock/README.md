# 状態画面 モック（Issue #236 第 1 段階・#238）

`touryou ui` で開く状態画面を大きく作り直すための、**静的なモック**です。人が見て直すためのもので、本番のコード（`packages/` 以下）は変えていません。

## 開き方

ブラウザで `docs/ui-mock/index.html` を開きます（ファイルをそのまま開くだけ。サーバーは要りません）。

- 外部の通信・外部のフォントはありません（HTML・CSS・インライン SVG と、ページの中の 2 つの script だけ。1 つは WebGL の背景、もう 1 つは明暗・タブなどのモック用の操作）。
- 左上は、開いているリポジトリ名（ダミー: `comcreate/sample-repo`）。製品名 `touryou` は小さく添え、幅 640px 以下では隠します。ブラウザのタブの題（`<title>`）も、リポジトリ名を先に書きます。
- 上のバーの「◐ 自動」で、OS に合わせる → 明るい → 暗い と切り替わります。OS の設定（`prefers-color-scheme`）にも従います。背景の色も一緒に変わります。
- 画面の組み方は見本（`ref/sample.html`）どおり、上のバー＋3 列（あなたの番・やり取りの図・作業のようす）で、画面全体はスクロールせず、列の中だけスクロールします（900px 以上）。3 列の後ろに、動く全面の背景が透けて見えます。
- 3 列に出ない部品（接続切れ・トークン入力・確認の欄・設定の窓・管理など）は、同じページの下の「部品の見本帳」に並べています（上の歯車を押すと、設定の窓へ移ります）。
- 900〜1279px は、左に「あなたの番」、右に「図（上）＋作業のようす（下）」。1280px 以上は 3 列。899px 以下は 1 列で、下のタブ（出番／図と作業）で切り替えます。
- スマホの幅（400px）は、ブラウザの幅を狭めるか、開発者ツールの端末表示で確かめます。
- 設定の窓の「動きを止める」を入れると、背景がその時点の絵で止まり、線の動きも止まります。OS の「視差効果を減らす」（`prefers-reduced-motion`）でも止まります。
- WebGL が使えないブラウザ（または、開発者ツールで WebGL を切ったとき）は、代わりに静的な SVG の背景が出ます。
- 画面の値はすべてダミーです（実際のトークン・パス・ID は書いていません）。

## 全面の背景（WebGL）

`ref/architect_backgrounds.tsx` の `ModernBlueprintBackground` を、React を使わない素の JS と、全面に固定した `<canvas id="bg-gl">` の WebGL に移しました（`index.html` の `<script id="bg-webgl">`）。

- **シェーダーは見本のまま**です。等角投影の傾き（`tilt`・回転 0.42）、斜めに流れる 2 段の方眼（細・太）、太い方眼の交点の小さな十字、大工・設計道具 6 種（差し金・コンパス・金槌・のこぎり・のみ・鉛筆）の距離関数と色、道具の回転・浮遊・明滅、2 層の光の塵の瞬き、動く環境光、ビネット、紙の粒。違いは、高い精度（`highp`）が使えない端末のために `precision` を分岐したことだけです。
- **画面の大きさ**: 毎回の描画の前に、canvas の CSS の箱（全面に固定）の幅・高さ × `devicePixelRatio`（上限 2。見本と同じ）に canvas を合わせます。`resize` と、`devicePixelRatio` の変化（別の画面へ窓を移したときなど。`matchMedia("(resolution: …dppx)")` で見張る）でも描き直します。
- **明暗**: `html` の `data-theme`（`light`・`dark`・なし＝OS に合わせる）と、OS の `prefers-color-scheme` から決め、シェーダーの `u_isDark` に渡します。`MutationObserver` で `data-theme` の変化を見るので、明暗の切り替えのボタンと結び付いていません。
- **動きを止める**: `html` の `.still`（設定の「動きを止める」）か `prefers-reduced-motion: reduce` のとき、`requestAnimationFrame` を止め、時間をその値で凍らせて 1 枚だけ描きます。止めている間も、明暗・大きさが変わったら 1 枚描き直します。時間は積み上げで持つので、動かし直しても絵が飛びません。最初から止まっているときも道具が見えるよう、時間は 24 秒から始めます。
- **WebGL がないとき**: 既定は、静的な SVG の背景（`.bg`）が見えている状態です。WebGL で最初の 1 枚を描けたときだけ `html` に `.gl` を付け、CSS で SVG を隠します。WebGL のコンテキストが取れない・シェーダーが通らない（理由はコンソールに出す）・コンテキストを失った（`webglcontextlost`）ときは、`.gl` がなく、SVG が出ます。コンテキストが戻ったら（`webglcontextrestored`）、作り直します。
- **別のファイルに出せる書き方**: 背景の script は、ページのほかの script に頼りません。ページとのやり取りは「`canvas#bg-gl` に描く」「`html` の `data-theme`・`.still` と OS の設定を読む」「`html` に `.gl` を付け外しする」の 3 つだけです。本番では、この script を丸ごと `/ui/` の配信物（例 `bg-webgl.js`）にすれば、CSP が `'self'` だけでも動きます（シェーダーは JS の文字列なので、別のファイルは要りません）。

代わりの SVG の背景（前の段階で作ったもの）は、方眼 2 段・交点の十字・道具 6 種の輪郭・光の塵・ビネットを、静止した絵と、ごくゆるい平行移動（120 秒）で描きます。

## 面（グラスモーフィズム）

上のバー・3 列の窓・カード・窓のタブ・設定の窓・関係図の盤と箱を、半透明の面にしました。

- **外の窓**（上のバー・3 列の窓・見本帳の台・スマホの下のタブ）: 背景に直接載る面です。値は見本（`ref/sample.html` の `--glass-*`）に合わせました。塗りは明 `rgba(244,241,234,.25)`・暗 `rgba(22,20,18,.45)`、`backdrop-filter: blur(16px) saturate(160%)`、縁は明 `rgba(255,255,255,.45)`・暗 `rgba(255,245,235,.12)`、影は明 `0 4px 16px rgba(0,0,0,.05)`・暗 `0 8px 32px rgba(0,0,0,.35)`。
- **中の面は塗りを重ねません。** カード・作業の札・承認の欄・受信箱の項目・設定の窓・確認の欄・ボタンなどは、ほぼ透明（明 6%・暗 3%）にして、細い縁（`--edge`）と上辺の光の線だけで区切ります。窓の見出し・窓のタブ・窓の下の帯・関係図の盤は、塗りなしです。前の版（外 48% の上に中 32% を重ね、実効 65〜70%）は濃すぎて背景が透けないと指摘されたため、こうしました。
- **中の面には `backdrop-filter` をかけていません。** `backdrop-filter` を持つ面は、その中の面にとっての「背景の根」になり、中でぼかしても WebGL の背景までは届かないためです。外の窓がぼかした背景が、そのまま中の面から見えます。
- **色で意味を示す部品の塗りはそのまま**: 状態の帯（左の太い線・動いているカードの緑の見出し）、押すボタン（柿・松）、状態の札（chip）、出番の行の柿の地、接続切れの帯など。
- **関係図の箱**: SVG の `rect` は `backdrop-filter` が効かないので、ごく薄い塗り（明 8%・暗 5%）と、上辺の光の線（`.hl` の線）で面にしています。盤の後ろは、外の窓がぼかしています。線の上の札（`.pill`）と出入口の点（`.pd`）は、線が文字の下を通らないよう、不透明のままです。
- **入力欄**（トークン・規則・対象の ID）は、打った文字を読みやすくするため、不透明のままです。

## 文字を読みやすくするための決め

- 本文のコントラストは 4.5:1 以上を目標にしています。面を薄くしたので、面全体を濃くする代わりに、**明の文字の色を濃くしました**: 補足 `#51565d` → `#474c53`、藍 `#2a5fa8` → `#24548f`、柿 `#b04a00` → `#974000`、松 `#2c6b44` → `#275f3c`、黄 `#7a5c00` → `#6b5000`。暗の文字の色は変えていません（暗い地の上で十分に高いため）。
- いちばん厳しいのは、窓の上の文字（`.lead`・`.note`・`.who`・窓の見出しなど）の後ろに、道具の濃い塗り（明: 紫 `0.38, 0.20, 0.72`、暗: 真鍮 `0.98, 0.75, 0.25`）が来たときです。そのときの見込みが、下の表です。
- 下の値は、背景を「道具の塗りが真後ろに来て、ぼかしで平らになった色」と置いた手計算の見込みです。色の検証の道具や、実機の画面では確かめていません。細い線（方眼・道具の輪郭）が文字のすぐ後ろに来たところで読みにくければ、その文字の下だけにごく薄い塗りを足します（面全体は濃くしない）。

- 押すボタン（柿の地に白・暗は黒）と状態の札（chip）は、地の色が不透明なので、背景の影響を受けません。
- 関係図の線の色は、飾りでなく、札の文字と記号でも同じ内容を示しています。

## 見本から取り入れたこと

見た目の方針（`ref/sample.html`）:

- **配色の語**: 柿（あなたの出番・答え待ち）・松（動いている）・朱（失敗）・黄（止まっているかも）・藍（上り・リンク・焦点）。明暗それぞれに値を持ち、状態は色だけでなく「▶ ● ✓ ✕ ‖」の記号と文字でも示します。
- **すりガラスの面**: 上の「面（グラスモーフィズム）」の節のとおり。
- **文字**: 本文 15px・行間 1.7。見出しは等幅で字間を広げた小さな札（`01 接続と通知` など）。関係図の札も等幅。
- **カードの形**: 角丸 8〜14px。状態の帯（左の太い線・動いているカードの緑の見出し）。上の状態の札（chip）は丸薬の形。
- **関係図**: 左が親、右が子。親の右に細いバー、線ごとの出入口の点。折れ線の角を丸め、種類ごとの色と、「↑ 判断 3 分前」の札を線の上に置く。新しいほど濃く太く、古いほど薄く細く。送ったが届いていない線は破線を流す。
- **余白とタッチ**: 押せるものは 44px 以上。スマホは 1 列。
- **画面の組み方**: 上のバー＋3 列、列の中だけスクロール、各列に窓の見出しとタブ、スマホは下のタブ 2 つ。
- **答えのボタン**: カードの中の答えのボタンは、横幅いっぱいの大きいボタン（高さ 48px、広いときは横に等分）。

全面の背景（`ref/architect_backgrounds.tsx`）: 上の「全面の背景（WebGL）」の節のとおり、シェーダーをそのまま使っています。

## 取り入れなかったこと

- **React**: 背景は、素の JS と WebGL にした。
- **見本の明暗の切り替えのボタン**（画面の下の「Light Mode」）: このモックの上のバーの明暗の札と、設定の窓の明暗で切り替える。
- **sample.html のオーロラ（canvas のぼかし）**: 全面の背景は architect_backgrounds.tsx を使う指示なので採らない。
- **sample.html の見本用の操作**（接続を切ってみる・案の一覧）と、画面の言語・設定の保存、関係図のドラッグ・ズームの動き: 見た目だけを置いた（ボタンは置いてあるが、押しても何も起きない）。
- **見本の仮の言葉**（注文画面・支払い方法など）は、そのままダミーとして使った。

## 守っていること

- **キーボードの焦点**: 3px の藍の輪郭（`:focus-visible`）。関係図の箱は Tab で届き、焦点で縁が太くなる。「本文へ移る」のリンクあり。窓のタブは左右の矢印・Home・End で移れる。
- **関係図の文字**: 札・箱の文字は図の座標で 12.5〜14px。幅 1440px の中央の窓では、ほぼ等倍（約 1.05 倍）で出る見込み（実機の計測はしていない）。
- **横スクロール**: 本文・窓・カードに `min-width:0`・`minmax(0,1fr)`・`overflow-wrap:anywhere` を入れている。左上のリポジトリ名は、長いときは「…」で切る。幅 375px・400px の実機表示は、このモックの作成時には確かめていない（見る人が確かめる）。
- **動き**: `prefers-reduced-motion` と、設定の「動きを止める」で、背景（WebGL・SVG とも）・接続の丸の呼吸・破線の流れを止める。
- **読み上げ**: 背景の canvas と SVG は `aria-hidden`。状態は文字でも示し、矢印には `aria-label`（上り・下り）、図には `role="group"` とラベル。
- **明暗**: `prefers-color-scheme` と、明暗の手動の切り替え（`data-theme`）の両方。

## 確かめていないこと

このモックを作った作業では、ブラウザで開いて見ることも、スクリーンショットを撮ることもできませんでした。次のことは、見る人が確かめてください。`index.html#theme=dark`（または `#theme=light`）で開くと、その明暗で始まるので、headless のブラウザでスクリーンショットを撮るときに使えます。

- WebGL の背景が描かれ、方眼が流れ、道具が回って浮かび、塵が瞬くこと（シェーダーは見本のままなので、見本と同じ絵になる見込み）。
- 「動きを止める」と OS の「視差効果を減らす」で止まること。WebGL を切ると SVG の背景が出ること。
- 明・暗とも、列の後ろに WebGL の方眼と道具がはっきり見えること。上の表のコントラストの見込みが、実際の画面でも保たれること。
- 明・暗・スマホの幅（375px・400px）で崩れないこと。

## 次の段階

ブラッシュアップのあと、この見た目になるように、`packages/daemon/src/api/ui-assets.ts` と `packages/daemon/src/ui/*` を直します。直すときの注意（モックでは扱っていないこと）:

- CSP が `'self'` だけを許すため、インラインの `<script>`・`<style>` は置けない。WebGL の背景の script（`#bg-webgl`）は、丸ごと `/ui/` の配信物の別のファイルにする（シェーダーは JS の文字列なので、そのまま入る）。代わりの SVG の背景も、インラインではなく別のファイルにするか、CSS の中で作る形が要る。
- リポジトリ名は、daemon が知っている、開いている木の作業ツリーから出す（モックはダミー）。
- モックの明暗の切り替えは、本番では既存の `theme-light`・`theme-dark` のクラスの仕組みを使う。背景の script が見る `data-theme` は、そのクラスに読み替える。
- 描画は `textContent` と `createElement` だけ（`ui-assets.test.ts` の走査）。
