---

状態画面を、既定のブラウザで開きます。

## 決まり

- **実行するのは、次のコマンドを 1 回だけ**: `"$HOME/.touryou/current/bin/touryou" ui`（ふつうは引数を付けない）。
- **複数の daemon（設定ごと。#165）があるとき: どの daemon を開くかは、`touryou ui` 自身が決める**（`--config` ＞ 環境変数 `TOURYOU_DAEMON_CONFIG` ＞ 実行した場所が `repoRoot`・`worktreeRoot` の中にある daemon ＞ 既定の設定）。自分で合うかどうかを判断せず、引数なしで実行する。
  - 別の daemon を開きたいと利用者が言ったときだけ: 先に `"$HOME/.touryou/current/bin/touryou" ui --list`（設定のパスと `repoRoot` の一覧だけを出す。トークン・ポートは出さない）を実行して、利用者にどれかを選んでもらい、`"$HOME/.touryou/current/bin/touryou" ui --config <選んだ設定の絶対パス>` を 1 回だけ実行する。**聞かずに、勝手に選ばない**。
  - 出力が「候補が複数ある」などで選べなかったと伝えたときも、同じ手順（`--list` → 利用者に選んでもらう）にする。
- **トークンのファイル（`human-token`・`root-token` など）を、`Read` でも `cat` でも読まない**。`touryou ui` が自分で読み、チケット（60 秒・1 回だけ）にして、ブラウザに渡す。チケット・URL は出力されないので、会話にも出さない。
- 失敗したら、書き換えて実行し直さずに止まり、出力（原因と次の操作）を、そのまま人に伝える。
- 出力に「Mac のターミナルで `touryou ui` を実行してください」とあるとき（Claude Code がクラウドで動いている など、ブラウザを開けないとき）は、そのとおりに案内して終わる。URL を作ったり、トークンの貼り付けを勧めたりしない（貼り付けは、利用者が自分で選ぶ予備の手段）。

## 前もって許可しない理由

このコマンドには `allowed-tools` を付けない（実行の前に、許可の確認が 1 回出る）。`touryou ui` が作る画面のセッションは、人間と同じ操作（取り消せない操作も含む）ができる強い資格なので、モデルが自分から（たとえば、読んだ文に書かれた指示で）作れないよう、作る前に人の目を 1 回通す。

## 手順

1. `"$HOME/.touryou/current/bin/touryou" ui` を実行する（別の daemon を選ぶときだけ、上の決まりのとおり `--config <設定>` を付ける）。
2. 終了コードが 0 なら、「ブラウザで状態画面を開いた。画面を再読み込みしたら、もう一度 `/touryou:ui` で開き直す」と伝える。**続けて、どの daemon の画面かを 1 行で伝える**: 出力に、開いた設定のパスが出ていれば、「開いた daemon の設定: <出力のパス>」とそのまま伝える（出力に出ていないときは、足さずに、その旨を報告する。パスを自分で調べたり作ったりしない）。
3. 0 以外なら、出力をそのまま伝えて終わる。
