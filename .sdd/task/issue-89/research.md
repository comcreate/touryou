### 1.4 「判断待ちはありません」なのに「要対応 7」が出る理由（コードで確認）

- 「判断待ち」の欄は、`view.decisions`（未回答の判断）と `view.extensions`（未判定の拡張要求）が**両方とも空**なら「判断待ちはありません」と出す（`ui-assets.ts` の `render`）。
- 「要対応 N」は、`UiNode.openItems`。`uiViewOf` は、**解決していない受信箱の項目すべて**（`digest` を除く）を数える。`progress`・`done`・`info`・`violation` も入る。
- 受信箱の項目は、人が解決にする操作がないため、進み具合や知らせがたまる一方になる。
- よって、「要対応」は「人が答えること」ではなく「未解決の記録の数」。名前と中身が合っていない。案では、「要対応」は人の操作が要るもの（判断・範囲の頼み・止まっているかも・停止の代行依頼）だけを数える。

### 2.4 B を選ぶときの決まりの変え方と守り

- `svgEl(tag, attrs)` を 1 つだけ足す。タグは `svg`・`g`・`rect`・`path`・`text`・`title` の許可リスト。属性も許可リスト（`x`・`y`・`width`・`height`・`rx`・`d`・`class`・`viewBox`）で、**値は数か、決まった形（`d` は `M`・`L`・`C` と数だけ）**しか通さない。文字（題など）は `text` 要素の `textContent` にだけ入れる。
- 走査の試験：`createElementNS`・`setAttribute` は `svgEl` の中の 1 か所だけにあることを数えて確かめる（いまの「通信は `callOperation` の 1 か所だけ」と同じやり方）。`href`・`on*`・`style` 属性・`foreignObject`・`use`・`a` は許可リストに入れない。
- CSP は変えない（インラインの SVG 要素を JS で作るのは、`'self'` のままで描ける）。

### 2.5 勧め

**B（SVG を自前で描く）**。理由：守りの変更が 1 関数に閉じ、試験で縛れる。依存も配布物も増えない。木と矢印には Rete.js の編集の力は要らない。Rete.js は、編集の道具を前提にした作りで、素の DOM の道が確かめられず、自動配置に重い依存（elkjs）が要る。図が大きくなって自前で追えなくなったら、そのときに C を考え直す。

## 3. 画面の案（[mock.html](mock.html)）

- **いまあなたがすること**（いちばん上・色の枠）：判断を求む・範囲を広げる頼み・止まっているかも、を数と一覧で出す。それぞれに、答えのボタン、またはコマンドと「写す」ボタン。何もなければ「いまはありません」。
- **作業ごとのようす**：子 1 つを 1 枚のカード。題・役割・状態・最後の動き（「4 分前」）・要対応の数。ID は小さく、写すボタンつき。受信箱の項目は、そのカードの中で新しい順。種類は日本語（進み具合・済んだ・止められた操作・知らせ…）。時刻は手元の時刻と「何分前」。長い文は開いて全文。済んだ子・アーカイブした子は「済んだ作業」にたたむ。
- **止められた操作**：カードの中に、何が止められたかと、「広げる…」「断る」「子に別の道を伝える…」を、その場で出す（上の欄と同じ操作）。
- **子への操作**：カードの「この子への操作」にたたみ、ボタンごとに短い説明を添える。
- **管理**（たたんだ欄）：アーカイブした作業の削除・自動削除の保留・捨てた作業の保管。取り消せないものは赤の字と説明。細かい選び方は、さらにたたむ。
- **関係図（案）**：親子を実線、メッセージを点線の矢印（誰から誰へ・いつ）、人の操作が要る子はオレンジの枠。見るだけ。
- **言葉**：「SSE・seq・墓標・一覧を読み込む」は出さない（「つながっています（更新は自動）」「削除の記録」「保管の一覧を見る」など）。
- **接続**：#88 で変わる前提で、上の 1 行だけにした。
### 3.1 利用者の追加の望み（11-17）：動きと、上り・下りの分け

- **上り・下りを分ける**：関係図は、ノードを真ん中の 1 列に並べ、**上り（子 → 親：報告・判断の求め・頼み）は上の帯**、**下り（親 → 子：答え・指示・依頼）は下の帯**に、弧で描く。色も分ける（上り＝青、下り＝紫、人の操作が要るもの＝オレンジ）。カードの項目にも「▲ 子から」「▼ 子へ」を付ける。
- **動き（見本に入れたもの）**
  - 線の流れ（点線が向きに沿って流れる。人の操作が要る線は速く・太く）と、線の上を動く点（向きがひと目で分かる）。
  - 最初に線が描かれていく動き、新しい項目が来たときの線の描き直しと項目の光り。
  - 人の操作が要るノードの枠が脈打つ。状態の丸（実行中・止まっているかも）が脈打つ。
  - 「いまあなたがすること」の行がすべって入る・答えるとすべって消え、数がはねて減る。カードが順に浮き上がる。たたみの開閉。
  - ノードに指を置くと、そのノードのやり取りだけが浮かぶ（ほかは薄くなる）。押すと、その子のカードへ動いて光る。
  - **止める道**：OS の「視差効果を減らす」（`prefers-reduced-motion`）では、はじめから止める。画面の「動きを止める」でも止まる。動きは意味を足すだけで、止めても読めること（色・▲▼・文言）を守る。
- **本番での作り方と守り**（D2 で B を選んだとき）
  - 線の流れ・脈打ち・出入りは、**CSS の `@keyframes` とクラスの付け外しだけ**で作る（CSP の `style-src 'self'` のまま。`app.css` に書く）。JS は `className`・`classList` を変えるだけ。
  - 動く点は、見本では SVG の `animateMotion` を使った。本番では、要素を増やさず、CSS の `offset-path` で点を動かす案を勧める。ただし `offset-path` を JS から決めるには `style.offsetPath` が要り、走査のプロパティの許可リストに足すことになる（`svgEl` と同じく、1 か所に閉じて、値は数で組んだ `path('M … Q …')` だけにする）。`animateMotion` を使うなら、`svgEl` のタグの許可リストに足す（属性は `dur`・`repeatCount`・`path`。`path` は `d` と同じ検査）。
  - 弧の形は、ノードの並びから数で計算する（上りは `y` を小さく、下りは大きく）。子が多いときは、弧の高さを距離に比べて決め、ラベルが重なるときは時刻を省く。
- **決めてほしいこと D8**（下の表）。

- 見本は `details`・`summary`・`code` を使う。本番では、許可リスト（`TAGS`）に `details`・`summary`・`code` を足す必要がある（どれも属性なしで使い、危ない働きはない）。**決めてほしいこと D4**。
