### 1.4 「判断待ちはありません」なのに「要対応 7」が出る理由（コードで確認）

- 「判断待ち」の欄は、`view.decisions`（未回答の判断）と `view.extensions`（未判定の拡張要求）が**両方とも空**なら「判断待ちはありません」と出す（`ui-assets.ts` の `render`）。
- 「要対応 N」は、`UiNode.openItems`。`uiViewOf` は、**解決していない受信箱の項目すべて**（`digest` を除く）を数える。`progress`・`done`・`info`・`violation` も入る。
- 受信箱の項目は、人が解決にする操作がないため、進み具合や知らせがたまる一方になる。
- よって、「要対応」は「人が答えること」ではなく「未解決の記録の数」。名前と中身が合っていない。案では、「要対応」は人の操作が要るもの（判断・範囲の頼み・止まっているかも・停止の代行依頼）だけを数える。

### 2.4 B を選ぶときの決まりの変え方と守り

- `svgEl(tag, attrs)` を 1 つだけ足す。タグは `svg`・`g`・`rect`・`path`・`text`・`title` の許可リスト。属性も許可リスト（`x`・`y`・`width`・`height`・`rx`・`d`・`class`・`viewBox`）で、**値は数か、決まった形（`d` は `M`・`L`・`C` と数だけ）**しか通さない。文字（題など）は `text` 要素の `textContent` にだけ入れる。
- 走査の試験：`createElementNS`・`setAttribute` は `svgEl` の中の 1 か所だけにあることを数えて確かめる（いまの「通信は `callOperation` の 1 か所だけ」と同じやり方）。`href`・`on*`・`style` 属性・`foreignObject`・`use`・`a` は許可リストに入れない。
- CSP は変えない（インラインの SVG 要素を JS で作るのは、`'self'` のままで描ける）。

### 2.5 勧め

**B（SVG を自前で描く）**。理由：守りの変更が 1 関数に閉じ、試験で縛れる。依存も配布物も増えない。木と矢印には Rete.js の編集の力は要らない。Rete.js は、編集の道具を前提にした作りで、素の DOM の道が確かめられず、自動配置に重い依存（elkjs）が要る。図が大きくなって自前で追えなくなったら、そのときに C を考え直す。

## 3. 画面の案（[mock.html](mock.html)）

- **いまあなたがすること**（いちばん上・色の枠）：判断を求む・範囲を広げる頼み・止まっているかも、を数と一覧で出す。それぞれに、答えのボタン、またはコマンドと「写す」ボタン。何もなければ「いまはありません」。
- **作業ごとのようす**：子 1 つを 1 枚のカード。題・役割・状態・最後の動き（「4 分前」）・要対応の数。ID は小さく、写すボタンつき。受信箱の項目は、そのカードの中で新しい順。種類は日本語（進み具合・済んだ・止められた操作・知らせ…）。時刻は手元の時刻と「何分前」。長い文は開いて全文。済んだ子・アーカイブした子は「済んだ作業」にたたむ。
- **止められた操作**：カードの中に、何が止められたかと、「広げる…」「断る」「子に別の道を伝える…」を、その場で出す（上の欄と同じ操作）。
- **子への操作**：カードの「この子への操作」にたたみ、ボタンごとに短い説明を添える。
- **管理**（たたんだ欄）：アーカイブした作業の削除・自動削除の保留・捨てた作業の保管。取り消せないものは赤の字と説明。細かい選び方は、さらにたたむ。
- **関係図（案）**：親子を実線、メッセージを点線の矢印（誰から誰へ・いつ）、人の操作が要る子はオレンジの枠。見るだけ。
- **言葉**：「SSE・seq・墓標・一覧を読み込む」は出さない（「つながっています（更新は自動）」「削除の記録」「保管の一覧を見る」など）。
- **接続**：#88 で変わる前提で、上の 1 行だけにした。
### 3.1 利用者の追加の望み（11-17）：動きと、上り・下りの分け

- **上り・下りを分ける**：関係図は、ノードを真ん中の 1 列に並べ、**上り（子 → 親：報告・判断の求め・頼み）は上の帯**、**下り（親 → 子：答え・指示・依頼）は下の帯**に、弧で描く。色も分ける（上り＝青、下り＝紫、人の操作が要るもの＝オレンジ）。カードの項目にも「▲ 子から」「▼ 子へ」を付ける。
- **動き（見本に入れたもの）**
  - 線の流れ（点線が向きに沿って流れる。人の操作が要る線は速く・太く）と、線の上を動く点（向きがひと目で分かる）。
  - 最初に線が描かれていく動き、新しい項目が来たときの線の描き直しと項目の光り。
  - 人の操作が要るノードの枠が脈打つ。状態の丸（実行中・止まっているかも）が脈打つ。
  - 「いまあなたがすること」の行がすべって入る・答えるとすべって消え、数がはねて減る。カードが順に浮き上がる。たたみの開閉。
  - ノードに指を置くと、そのノードのやり取りだけが浮かぶ（ほかは薄くなる）。押すと、その子のカードへ動いて光る。
  - **止める道**：OS の「視差効果を減らす」（`prefers-reduced-motion`）では、はじめから止める。画面の「動きを止める」でも止まる。動きは意味を足すだけで、止めても読めること（色・▲▼・文言）を守る。
- **本番での作り方と守り**（D2 で B を選んだとき）
  - 線の流れ・脈打ち・出入りは、**CSS の `@keyframes` とクラスの付け外しだけ**で作る（CSP の `style-src 'self'` のまま。`app.css` に書く）。JS は `className`・`classList` を変えるだけ。
  - 動く点は、見本では SVG の `animateMotion` を使った。本番では、要素を増やさず、CSS の `offset-path` で点を動かす案を勧める。ただし `offset-path` を JS から決めるには `style.offsetPath` が要り、走査のプロパティの許可リストに足すことになる（`svgEl` と同じく、1 か所に閉じて、値は数で組んだ `path('M … Q …')` だけにする）。`animateMotion` を使うなら、`svgEl` のタグの許可リストに足す（属性は `dur`・`repeatCount`・`path`。`path` は `d` と同じ検査）。
  - 弧の形は、ノードの並びから数で計算する（上りは `y` を小さく、下りは大きく）。子が多いときは、弧の高さを距離に比べて決め、ラベルが重なるときは時刻を省く。
- **決めてほしいこと D8**（下の表）。

- 見本は `details`・`summary`・`code` を使う。本番では、許可リスト（`TAGS`）に `details`・`summary`・`code` を足す必要がある（どれも属性なしで使い、危ない働きはない）。**決めてほしいこと D4**。

### 6.1 Rete.js の組み込みの案

#### 描画のプラグインの比べ（npm の tarball の中身で確認。2026-11-17）

- `rete-area-plugin`・`rete-react-plugin` の中の `innerHTML` は、`holder.innerHTML = ""`（中身を消すだけ）の形。文字を入れる使い方ではない（中身で確認）。
- 出典：`https://registry.npmjs.org/<名前>`（版・依存）、各パッケージの tarball の `dist/*.min.js`（大きさ・中の API）。

#### 自動の配置

- elkjs（EPL-2.0 OR GPL-3.0、展開 8.2 MB）は使わない。`rete-auto-arrange-plugin` も使わない（peer に elkjs が要る）。
- 位置は自前で計算し、`area.translate(nodeId, { x, y })` で渡す。**木は、深さで段に分ける**（11-17 の利用者の答え。横 1 列はやめる）。根が上、深いほど下。
- 計算の決まり（整った木の並べ方。`layoutOf(nodes, size) → { id, x, y }[]`）：
  1. 段：`y = 深さ × (箱の高さ ＋ 段の間)`。
  2. 葉（子のないノード）を、深さ優先の順に、左から 1 つずつ置く：`x = 葉の番号 × (箱の幅 ＋ 横の間)`。
  3. 親は、**子の並びの真ん中の上**に置く：`x = (最初の子の x ＋ 最後の子の x) ÷ 2`。子が 1 つなら、その真上。
  4. 兄弟の並べ方は、**生まれた順（記録の seq）**で固定する。人の操作が要る子を先にすると、状態が変わるたびに図が組み変わって目が追えないので、要対応は色と脈打ちで示す。
  5. 幅は葉の数で決まる（全体の幅 ＝ 葉の数 × (箱の幅 ＋ 横の間)）。画面に入らないときは、area のプラグインで全体が入るように縮め（拡大・パンは残す）、それでも小さすぎる（例：葉が 12 を超える）ときは、**済んだ・アーカイブした子を「済んだ子 N」の 1 つの箱にまとめる**。まだ多いときは、1 つの親の子を 2 段に折り返す。
  6. 全部が 1 本の鎖（どのノードも子が 1 つ以下）なら、同じ決まりで縦 1 列になる。縦に長すぎるときだけ、横に倒す（左が根）案を試作で比べる。
  7. 親が見えないノード（表示モデルの上限で切れた・形の崩れた ID）は、根の段の右端に「親の見えない子」としてまとめて置く。`dependsOn`（依存）は木の枝にしない（細い点線で横に結ぶか、出さない。試作で決める）。
- 試験：根だけ・鎖・横に広い木・深さの不揃いな木・まとめ（済んだ子 N）・親の見えない子、を vm で確かめる（位置が重ならない・親が子の真ん中の上・同じ入力で同じ出力）。
- 計算は純粋な関数（`layoutOf(nodes) → {id, x, y}[]`）にして、vm で試験する（いまの「画面の純粋な部分」の試験と同じ）。

#### 読み取り専用

- `rete-readonly-plugin`（2.0.2、0.9 KB）で、つなぐ・動かす・消すを止める。中身の挙動は文書が読めず**未確認**。足りなければ、area の合図（`nodepicked`・`translate` など）を受けて、返り値で止める（area のプラグインの決まりの作り。試作で確かめる）。
- 拡大と画面の移動（パン）は残す（見るための操作）。

#### 上りと下りの線・流れの動き

- **やり取りの線は、木の枝に沿わせる**。親の箱の下と子の箱の上を結ぶ 1 本の枝に、**上りと下りの 2 本の道を並べる**（枝の中心から、左右に 5〜6 px ずらした 2 本）。決まり：**上りは枝の左側（矢印は上向き・青）、下りは枝の右側（矢印は下向き・紫）**。どの枝でも同じ側なので、慣れれば向きを色を見ずに読める。
- 枝そのもの（親子の関係）は、いつも細い灰色で描く。やり取りがある道だけ、色がついて流れる（`stroke-dashoffset`）。人の操作が要るやり取りは、オレンジで太く速く流れる。道の真ん中に、いちばん新しいやり取りの種類と「何分前」、2 件以上なら件数。
- 矢印の先は、`marker`（`url(#…)` の参照が要る）を使わず、道の端の向きから**小さな三角を数で計算して `path` で描く**（`svgEl` の許可リストを増やさずにすむ）。
- **Rete.js（R0）での作り方**：各ノードに、上の口（`up-out`：子 → 親の上り、`down-in`：親 → 子の下り）と下の口（`up-in`・`down-out`）を持たせ、上りと下りを**別のつながり**として足す（上り＝子の `up-out` → 親の `up-in`、下り＝親の `down-out` → 子の `down-in`）。図は読み取り専用で箱は動かないので、線の形は口の DOM の位置を測らずに、`layoutOf` の位置から計算する（area のプラグインの「つながりを描く」合図で、自前の `svgEl` で `path` を組む）。
- **段を飛ばすやり取り**（例：人 → 孫への答え、daemon → 統合への要約）：
  - (a) **木の道をたどる**：孫 → 子 → 統合の枝の道を順につなぐ。途中のノードには小さな「通過」の点。本当に中継されるもの（子の報告の要約が親を通るもの）に合う。
  - (b) **横の通り道**：木の右に縦の「通り道」を 1 本とり、そこを通る折れ線で結ぶ。中継しない直通（人の答え・daemon の知らせ）に合い、枝と重ならない。
  - 勧め：中継するものは (a)、直通は (b)。「人」は木の外（根の上、または右上）に 1 つの箱として置き、人とのやり取りは (b) の通り道を通す（色は人の操作のオレンジ）。
- **曲線と折れ線の比べ**（見本の担当が見本で並べて比べる）：

| | 曲線（縦向きの 3 次ベジエ） | 折れ線（下 → 横 → 下。角は丸める） |
|:--|:--|:--|
| 見た目 | やわらかい。木が小さいときに読みやすい | きっちり。木が広いと、横の線がそろって読みやすい |
| 2 本の道を並べる | 曲線をずらした線は正確には平行にならない（制御点もずらして近づける。幅 5〜6 px なら目立たない） | **正確に平行にできる**（縦と横の線を、同じだけずらす） |
| ラベルの置き場 | 曲線の真ん中（傾いた所） | 横の線の上（水平で読みやすい） |
| 動く点（`offset-path`） | そのまま使える | そのまま使える |
| `d` の命令 | `M`・`C` | `M`・`L`・`A`（角の丸め）または `Q` |
| 勧め | 子が数個まで | **広い木の既定**。迷ったらこちら |

- `svgEl` の `d` の検査は、`M`・`L`・`C`・`Q`・`A`・`Z` と数だけを通す（6.2 の表の「SVG」の行を、この命令の集合で直す）。
- 流れの動きは、CSS の `stroke-dashoffset` の `@keyframes`（`app.css`）。動く点は、CSS の `offset-path`（D8）。`prefers-reduced-motion` と「動きを止める」で止める。
- ノードに指を置いたときの浮かび上がりは、`classList` の付け外しだけ。
