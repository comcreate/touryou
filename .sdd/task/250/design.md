# #250 再生成できる ignored のファイルを、新しい作業ツリーに置く手段

## 結論

**既存の `touryou-worktree-files.json`（`packages/daemon/src/worktree-seed.ts`）で足りる。worktree 作成後の hook も、元のファイルが無いときの再生成コマンドも、足さない。**
そのうえで、読んで見つけた 2 つの穴を直し、手順を docs に書く。

## 根拠（コードを読んで確かめたこと）

| 要件 | 既存の仕組み | 判定 |
|:--|:--|:--|
| 新しい作業ツリーに、ignored のファイルが置かれる | `provisionWorktree` が `git worktree add` のあとに `copySeed` する（`git-ports.ts`）。一覧は `<repoRoot>/.claude/touryou-worktree-files.json` の `files`（50 件まで） | 足りる |
| 設定者が信頼できる | 一覧は利用者の `repoRoot` の `.claude/` にあるファイル。子は `.claude/` を書けない（範囲・フックで拒否される）。パスは `..`・絶対パス・`.git`・repoRoot の外を指すリンクを、作業ツリーを作る前に拒否 | 足りる |
| 回収の「きれいか」から外れる | `seededPaths()` を `isClean`・`lossOf` が使う | 一部の形で穴あり（下の穴 2） |
| 元のファイルが無いとき | `planSeed` が `missing` に記録してスキップ。作業ツリーは作る | 足りる（利用者が `repoRoot` で 1 回取ればよい） |
| 大きなバイナリ | `copyFileSync`（クローンなし） | 穴 1（下） |

Renga の actionlint のバイナリは、1 つのファイルで、利用者が `repoRoot` で `scripts/fetch-actionlint` を 1 回実行すれば `repoRoot` に残る。それを写せばよいので、「作業ツリーごとに再生成する」必要がない。

## 見つけた穴と直し方

1. **コピーがクローンでない**: `copyFileSync` の既定は通常のコピー。`fs.constants.COPYFILE_FICLONE` を付けると、クローンできる環境（APFS）ではクローン（時間・容量を使わない）、できない環境では通常のコピーに落ちる（失敗にならない）。権限も写る。→ 付ける。
2. **丸ごと gitignore のディレクトリの中のファイルが、「きれいでない」になる場合がある**: `git status --ignored=matching` は、丸ごと ignore のディレクトリを `!! dir/` の 1 行にまとめる。一覧にあるのは `dir/file` なので、`seeded.has("dir/")` が偽になり、回収が止まる。Renga の `binaries/` が、`.gitkeep` などの追跡ファイルを持たず、丸ごと ignore なら、この形になる。
   - 直し方: 一覧のファイルを含む `dir/` の行だけ、`--ignored=traditional -- <dir>` で、ファイルごとの行に開く。含まないディレクトリ（`node_modules/` など）は開かない（行が膨らむため）。
   - 一覧にないファイルが同じディレクトリにあれば、開いた行に出るので、これまでどおり「きれいでない」になる（隠さない）。
   - 試験: `worktree-seed.test.ts`「丸ごと gitignore のディレクトリの中のバイナリ」。

## 大きなバイナリのコピー（時間・容量・APFS）

- actionlint のバイナリは数 MB。通常のコピーでも問題ない大きさ。
- APFS の `clonefile` は、同じボリュームの中でだけ使える。`repoRoot` と `worktreeRoot`（既定は `~/.touryou-worktrees`）が別のボリュームなら、通常のコピーになる（失敗にはならない）。
- クローンは、書き込むと、その部分だけ別になる（コピーオンライト）。子が書き換えても、`repoRoot` のファイルは変わらない（コピーの約束と同じ）。

## 検討して、採らなかった案（推奨を添える）

| 案 | 内容 | 採らない理由 |
|:--|:--|:--|
| A（採用） | 既存の一覧 + クローン + 判定の穴の修正 + docs | 任意のコマンドを足さずに、課題を満たす |
| B | 作業ツリー作成後に走らせる設定したコマンド（hook） | daemon が、設定したコマンドを走らせる経路が増える。**安全面の設計**（下）が重く、課題（1 つのバイナリを置く）に対して過大。コマンドが長引くと、作業ツリーの作成（直列の `serial`）全体が止まる |
| C | 元のファイルが無いときに再生成するコマンド | B と同じ。さらに、再生成が失敗したときの扱い（作らずに失敗するか、続けるか）で、子の起動の成否が、ネットワークの状態で変わる |

### もし B・C を足すなら守ること（足さないが、将来のために明記する）

- 設定は、利用者の `repoRoot` の `.claude/` の信頼できるファイルだけ（子の入力・子の作業ツリーのファイルでは変えられない）。
- シェルを通さず、引数の配列（`execFile`）で走らせる。環境変数は絞る（`GIT_` を外す、など）。
- タイムアウトを必ず付け、直列の枠の外で走らせるか、短くする（作業ツリーの作成を長く止めない）。
- 失敗時は、作業ツリーを作らず、原因と次にすることを返す（黙って続けると、子が `cargo test` で原因の分からない失敗をする）。

## 判断してほしい点（親へ）

- **A で進めてよいか**（推奨: A）。B・C が要るなら、上の「守ること」を設計にして、別の束で実装する。
- Renga 側の `.claude/touryou-worktree-files.json` は、子が書けないので、利用者（または統括）が、`repoRoot` に置く。例は `docs/plugin.md`。

## 試験

- 追加（`packages/daemon/test/worktree-seed.test.ts`）: 丸ごと ignore のディレクトリの中のバイナリ（権限・きれい・同じディレクトリの別ファイルは「きれいでない」）、元のファイルがない（`missing`・作業ツリーは作る）、コピーに失敗（`skipped`・作業ツリーは作る）。
- 既存: 一覧の不正（`..`・絶対パス・`.git`・形）・repoRoot の外を指すリンクは、作業ツリーを作らずに失敗する。
