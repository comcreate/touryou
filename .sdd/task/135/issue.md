# CLI の子で、承認した場所へ Bash で書き込む形（cp・mkdir・git rm・git mv など）にも、承認を効かせる（v0.1.6 に入れる）

## 背景

#130 の直し（#133）で、CLI の子（`--permission-mode dontAsk`）が承認したコマンドに引数を足しても通るよう、「引数を足してよいコマンドの一覧」を足した。ただし、一覧に入れたのは、作業ツリーの外へ書けない・旗で任意のコードを動かせないと分かっている `git add`・`git status`・`git ls-files` だけにした（利用者の決め）。

次の形は、いまも、承認した形と完全に同じときだけ通る。

- Bash で書き込むコマンド（`cp`・`mv`・`mkdir`・`touch` など）：作業ツリーの中のシンボリックリンクを通って、外へ書けるため。
- `git rm`・`git mv`：足した引数（パス）が、子の書き込める場所の外を指せるため（例：`git rm docs/old.md` を承認すると、`git rm -r .` にも許可が付いてしまう。#133 のレビューの must）。

## したいこと

- 位置の引数（パス）を、子の書き込める場所（範囲の `writableLocations`。拡張で足した場所を含む）と**実パス**で照らし、すべてが中にあるときだけ、明示の許可（`permit: "extension"`）を付ける。
- 照らすときは、リンクを通った先（まだないパスは、今ある一番深い祖先の実パスに残りを足す。#113 と同じ考え方）で比べる。
- コマンドごとに許す旗の表を持つ（#133 と同じ作り）。

## 決めること

- 一覧に入れるコマンドと、それぞれ許す旗。
- glob（`*`）と空白を含むパスの扱い（#133 では完全一致だけ。glob はこれからも断る案、空白は引用符を正しく扱える作りができたら許す案がある）。

## 受け入れ基準

- [ ] 書き込める場所の中を指すときだけ、引数を足した形に明示の許可が付く
- [ ] リンクを通って外を指す形・外のパスを含む形には付かない
- [ ] 本物の daemon と git の作業ツリーで、`POST /v1/hook` を通す試験がある
- [ ] 子と人への文言（`scope_extend` の説明・承認の知らせ・skill・docs）を合わせ、`bash scripts/check.sh` が通る
