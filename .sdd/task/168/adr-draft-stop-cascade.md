# サブ統括停止時の孫の扱い 決定ログ（案）

> 案。判断 4 は未提出・未回答（推奨で記述）。

## 2026-11-22 サブ統括の停止は配下の動作中の孫を先に止める

- **Decision**: サブ統括を `node.stop` するとき、配下の動作中の孫を先に停止の依頼に載せる（後順。回収と同じ向き）。孫の停止がすべて確認されるまでサブ統括は `stopping` に留まり、確認できない孫がいれば `stopIncomplete` を理由付きで root の受信箱に出す。`done` の孫は人だけが止められる（#115）ので対象にしない。孫の成果は残し、root が `reclaim` で後始末をする。
- **Rationale**: 親だけが消えると、孫の依頼・報告の宛先がなくなり孤立する。親の付け替えを伴う案は、範囲の再検査・イベント・UI が増え、v0.1.7 には重い。
- **Rejected alternatives**: root が孫を引き取る — 付け替えの設計が要り、範囲の再検査・ログの事象が増える。孫がいる間は停止を拒否 — 人に手順が回る。連動せず digest で知らせるだけ — 孤立した孫が動き続ける。
