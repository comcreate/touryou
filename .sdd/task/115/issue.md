# v0.1.3 の実機の確かめで見つかった小さな点を直す（v0.1.6 に入れる）

## 背景

v0.1.3 の配る前の確かめ（Mac の実機）で、大きな不具合（#92 が CLI の子で効かない・関係図が見本と違う・状態画面の購読が 429 を受け続ける）のほかに、小さな点が見つかった。v0.1.3 は marketplace に出さず、直しをすべて入れて v0.1.4 として出す。

## 直すこと

### 状態画面（`packages/daemon/src/api/ui-assets.ts`）

- [ ] 受信箱の知らせの文に、子の題ではなく長いノード ID がそのまま出る（「子 node-… が止まっているかもしれない」など）。題を出し、ID はカードの ID の欄に任せる。
- [ ] 内部の言葉が残っている：「墓標」（管理の最終削除のボタン）、「範囲の拡張要求（command）」など。利用者の言葉にする。
- [ ] やり取りの一覧の「詳しく」のボタンが、列の幅が足りずに 2 行に折れる。
- [ ] 人から子への線（範囲の頼みの却下・判断の答え）の札が「→ 指示」になる。答え・却下などの種類の言葉にする。

### daemon

- [ ] 範囲の頼みや判断の答えを待っているだけの子にも、「止まっているかも」の知らせが出る。答え待ちの子は、知らせない。
- [ ] 同じ子の「止まっているかも」が、古い知らせと新しい知らせで 2 件重なって出る。同じ子の未解決の知らせは 1 件にまとめる。
- [ ] 受理のあとの後片付けで、統合に「セッションを止める」「セッションを消す」を続けて頼むが、止めた時点で一覧から消えるため、消す依頼が「うまくいかなかった」として受信箱に出る。止めた時点で消えていれば、消す依頼は済んだ扱いにする（または出さない）。
- [ ] 済んだと報告した（done）が受理していない子を、受理せずに片付ける道がない（`node.stop` は `alreadyFinished`、破棄は `notStopped` で断られる）。未達のまま受理しなくても、破棄して回収できる道を作る。

### CLI

- [ ] `touryou reclaim` が、窓口・人間のトークン・設定を環境変数で手で渡さないと動かない。`touryou ui` と同じく、設定から自分で読む（トークンは画面・履歴・引数に出さない）。
