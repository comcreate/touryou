# attach で MCP がつなぎ直されても、CLI の子が自分で紐付け直せるようにする（守りの考えを決めてから）（v0.1.6 に入れる）

## 背景

#136 の 3 つ目の穴。CLI の子の画面を `claude attach` で開くと、Claude Code が子の MCP（touryou-mcp）をつなぎ直す。子の資格情報（子ロールのトークン）は、安全のため mcp のプロセスのメモリにだけ持つ決まり（ファイル・環境変数に書かない）なので、プロセスが入れ替わるとトークンが消える。紐付けのコードは 1 回きりなので、子は自分で紐付け直せない。

#136（0.1.5）では、利用者の決めで「A：案内だけ」にした。外れたときに、画面と `bind_code_file_unavailable` の次の操作で、「統合の会話で node_bindCode を頼む」と案内する。この Issue は、人の手間を消す案を、守りの考えを決めてから扱うためのもの。

## 案（#136 の調べより）

- **B：つなぎ直しの紐付け**：新しい mcp が、セッションの ID（`CLAUDE_CODE_SESSION_ID`）・作業ツリー・ノード ID を daemon に送り、daemon は記録にあるそのノードのセッションの ID と作業ツリーが合うときだけ、トークンを出し直す。人の手間は消えるが、セッションの ID を知るだけで子の身元を取れるので、守りが今より弱くなる（フックの `sessionIdOnly` と同じ程度の信頼）。
- **C：紐付けのコードを、使ったあとも短い間残す**：同じセッションの ID からだけ使えるようにする。B と同じく、セッションの ID に頼る。

## 決めること

- セッションの ID を、どこまで子の身元として信じてよいか（守りの考え）。ほかに確かめられる値（作業ツリーの実パス・プロセスの親子・起動の記録など）を組み合わせられるか。

## 受け入れ基準

- [ ] 守りの考えを決めて、ADR に書く
- [ ] attach のあとも、子が人の手間なしに報告できる（試験あり）。守りが弱くなる所は、docs に書く
