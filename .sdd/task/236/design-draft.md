# 状態画面を確定したモックの見た目に作り直す（設計）

**仕様:** [touryou-ui.md](../../specification/touryou-ui.md)
**見た目の基準:** `docs/ui-mock/index.html` と `docs/ui-mock/README.md`（#238 で確定）
**置き場:** チケット番号は #236（#254 に含まれた）。旧の置き場 `.sdd/task/ui-status-screen-look/` は、統括が統合のときに改名・削除する（この子は触らない）。

実装後に削除してよい一時文書。

# 1. 作業の種別と理由

- **種別：新機能（小）**。変えるのは描画の層（`packages/daemon/src/api/ui-assets.ts`、`packages/daemon/src/ui/*`）だけ。
- daemon の窓口（API・配信の経路）、表示モデル（`ui-view.ts`）、保存先（`localStorage` の `touryou.ui.settings`）は変えない。

# 2. 利用者が決めたこと

| 項目 | 決定 |
|:--|:--|
| 段階分け | 5 段階（下の 3 節）。各段階で `pnpm build`・`pnpm test`・`scripts/ui-browser-check.mjs` が通り、単独でマージできる |
| 背景の script | 既存の `/ui/app.js` に含める。`/ui/` の経路は増やさない |
| リポジトリ名 | 今回は出さない（製品名のまま）。`ui-view.ts` は変えない |
| 彗星と流星 | 本番の彗星（`g-sent` の `.comet`）を、モックの流星に置き換えて 1 つにする |
| `color-mix` | 使えない古いブラウザは対象外 |
| 管理 | ダイアログにする。取り消せない操作の確認の欄（`#confirm`）も、管理の窓の中に出す |
| 確かめ | `pnpm test` の既存の試験で見られる範囲。ブラウザでの目視（明・暗・スマホ幅・日英・キーボード・動きを止める設定）は「未確認」と報告し、人が確かめる |
| 調整の窓 | モック専用。本番に入れない |

# 3. 段階

1. **色・面・上のバー・設定と管理のダイアログ**（この段階）
2. 3 窓とタブと幅の区切り
3. 関係図の作り直し（`ui-graph-js.ts` の束を含む）
4. 流星・火花・枠の光（彗星の置き換え）
5. 全面の背景（WebGL。`app.js` に含める）、docs・CHANGELOG の最終の直し

# 4. 段階 1 の設計

- **色**：明の配色を、「文字の色」（`--kaki`・`--matsu`・`--shu`・`--kiiro`・`--ai`。4.5:1）と「線・枠の色」（`--kaki-line`・`--matsu-line`・`--shu-line`・`--kiiro-line`・`--blue-line`。3:1）の 2 つに分ける。暗は、線の色を文字の色と同じ値にする。値は `docs/ui-mock/README.md` の表のとおり。背景 `--bg`・面 `--sheet`・`--card`・文字 `--fg`・`--muted`・`--line` も、モックの値（中立の白寄り、暗は `#060910`）に替える。本番の変数名は保つ。
- **面**：設定・管理の窓だけに、半透明の塗り `--dlg` とぼかし `--blur-dlg` を持たせる。窓の中の部品（ボタン・カード・空の表示）は不透明（`--sheet`）。外の窓・中の面のぼかしは、窓と列が入る段階 2 で入れる。
- **上のバー**：歯車を SVG（20px。歯は太さ 4 の線）にし、押せる範囲を 44px の丸にする。`aria-label`・`title` は現行のまま。
- **設定の窓**：幅は画面から左右 48px の余白（640px 以下は 16px）、高さは中身なり（最大で上下 48px の余白）。節の列は、1019px 以下は 1 列、1020〜1499px は 2 列（子の権限の規則は全幅）、1500px 以上は 3 列。説明の文は 40em まで。開き方・閉じ方・焦点の動きは、現行のまま（開いたら `#set-still` に焦点、Esc・閉じるで閉じて歯車へ戻す）。幕のクリックでも閉じる（押し始めと離した所の両方が幕の上のときだけ）。Tab の順は、動きを止める → 明暗 → 言語 → 管理 → 閉じる。
- **管理の窓**：設定の窓の下の「管理（取り消せない操作を含む）…」（`#to-admin`。朱の枠・警告の三角）から開く。押すと設定を閉じてから管理を開く（窓を重ねない）。閉じたら、焦点は歯車へ戻す。窓の中に、最終削除（`#purge`）・捨てた作業の保管（`#kept`）・確認の欄（`#confirm-admin`）を置く。本文の `details.admin` と、本文の `#confirm` は、管理の窓が閉じているあいだの確認（承認・拡張要求など）に使い続ける。管理の窓が開いているあいだ、確認は窓の中に出す（`renderConfirm` が出し先を選ぶ）。
- **文言**：`admin.title` を「管理（取り消せない操作を含む）」に替え、`admin.open`・`admin.close` を足す（日英）。

# 5. 段階 2 の設計

- **窓**：`#view` を 3 つの窓（`section.win`。`data-p` は `left`・`graph`・`right`）の舞台（`.stage`）にする。左は「あなたの番」（`#now-count` などの `.now` と `#todo`）、中は「やり取り」（図・一覧・凡例）、右は「作業ごとのようす」（`#cards`・`#finished`）。窓の見出しは `h2`（`#yours-title`・`#flows-title`・`#cards-title`）で、窓は `aria-labelledby` でその名前を持つ。既存の要素の id・`aria-label` は変えない。
- **入れなかったもの**：モックの窓の中のタブ（左の「判断・答え待ち／受信箱の知らせ」、右の「選んだ作業／作業の一覧」）は、本番に対応する中身（受信箱だけの一覧・選んだ作業の詳しい欄）がなく、表示モデルを変えない決めなので、入れない。承認の欄（`#approvals`）・確認の欄（`#confirm`）・知らせ（`#notice`）は、どのタブを出していても見えるよう、窓の外（舞台の上）に置いたままにする。
- **幅の区切り**：1280px〜は 3 列、900〜1279px は左＋右の上下（図が上）、900px〜は画面全体をスクロールせず、窓の中（`.wb`）だけスクロールする。〜899px は 1 列で、下のタブ（`nav.nav`。`#nav-yours`・`#nav-explore`。選んだほうに `aria-current="page"`）で「あなたの番」（左の窓）と「やり取りと作業」（中・右の窓）を切り替える（窓の見出しと同じ言葉）。選びは `#view` の `data-view` に持ち、ブラウザには残さない。開いたときは「あなたの番」から始め、データの更新では切り替えない。「あなたの番」のタブには件数の札（`#nav-count`。読み上げは隠した `#nav-count-sr`）を出す。900px〜では、`#approvals`・`#confirm`・`#notice` に高さの上限と中のスクロールを置き、`.stage` に最小の高さ 360px を置く（低い横長の画面では `main` がスクロールする）。`.now` の見出しは窓の `h2` の下の `h3`。一覧の「詳しく」（`openCard`）は、先に「図と作業」へ切り替える。
- **面**：外の窓（`.win`・`.top`・`.nav`）は、背面の `::before` に塗り `--win` とぼかし `--blur-outer` を持たせる。中の面（`.card`・`.task`・`.empty`・`.tlist`・`.board`）は塗り `--panel` とぼかし `--blur-inner`。入れ子の中の面と、設定・管理の窓の中のカードはぼかさない。値はモックのまま（明・暗の 3 か所）。
- **文言**：`pane.yours`・`pane.switch`・`pane.navExplore`・`pane.navCount`（日英）。

# 5.5 段階 3 の設計（関係図の作り直し。描画の層だけ）

- **範囲**：`graph-path.ts`（矢印の形）・`graph-entry.ts`（端子の形）・`app-text.ts`（凡例の文）・`ui-assets.ts`（関係図の CSS と凡例の HTML）。API・表示モデル（`ui-view.ts`・`graph-model.ts`）・保存先は変えない。束 `ui-graph-js.ts` は親が作り直す（この子は触らない）。流星・火花・背景（段階 4・5）と、本番の彗星（`.comet`）は触らない。
- **線**：実線を基本（太さ 1.8。答え待ちは 2.8、済んだものは 1.2）。破線は `g-sent`（7 5）と `g-unknown`（3 6）だけで、流れる動きは今のまま。色は線・矢印・端子・札が同じ `--c` を使う：上り `--blue-line`、下り `--matsu-line`、答え待ち `--kaki-line`、済んだ `--wire-over`（すべて段階 ① の変数。色の直書きなし）。新しいほど濃い（`a1`〜`a4`）は残す。
- **矢印**：塗った三角をやめ、塗らない開いた山形（先から 2 本の線。`M L M L`）にする。`PATH_PATTERN` の範囲内で、`svg-el.ts` の許可リストは変えない。端子は、丸（`rx` 3.5）から角の丸い四角（`rx` 1）へ。
- **箱**：不透明の面（`--sheet`）・細い縁（1.2px の `--line`）・上辺の光（`--hl`）。左の帯は、既定が動いている（`--matsu-line`）、答え待ち・止まっているかも・失敗は縁と帯を `*-line` の色に（縁 2px）。済んだ子は、箱そのものに `opacity` を付けず（図の盤が `backdrop-filter` を持つ）、中の要素と帯だけを 0.62 にし、帯は `--wire-over`。hover・focus は縁を `--ai` にする（輪郭の線は、キーボードの利用者のため残す）。状態の文字は 12.5px、動いている状態は `--matsu`。
- **札**：線の上の札は、等幅 12.5px で、文字の色（`--ai`・`--matsu`・`--kaki`・`--muted`。4.5:1）で出す。モックの札の地（`rect.pill`。幅 116 の固定）は、本番では文字の長さが言語・時刻で変わり、「何分前」の更新で幅が合わなくなるので、採らない。従来どおり、図の地の色の縁取り（`paint-order:stroke`）で読めるようにする。
- **済んだ子の札**：札の文字は `opacity` で薄くせず、色（`--muted`。4.5:1）で薄くする（PR #268 のレビュー）。済んだ線・矢印・端子は、`--wire-over`（3:1）に `opacity:.45` を重ねたまま。
- **凡例**：丸薬（不透明の面・細い縁・角の丸 999px）。線の見方の 3 行（`legend.delivered` 実線・`legend.sent` 破線・`legend.unknown` 点線。日英）を足した（線を実線にしたので、線の形に意味が付いたため）。文言は「・」で 2 つの状態に読めないようにし、形は見本の線で示す。
- **入れなかったもの**：親の右の細いバー（`.bar`）・モックの折れ線（本番の線は直線）・拡大縮小のボタンの 44px 化と左上への移動（`FIT_TOP`・隠した件数の札の位置に関わるので、段階 2 の窓の組み直しのあとに別に決める）・凡例の `details` 化。

# 5.6 段階 4 の設計（流星・火花・枠の光。描画の層だけ）

- **範囲**：`svg-el.ts`・`graph-path.ts`・`graph-entry.ts`・`app-text.ts`（凡例の文）・`ui-assets.ts`（CSS と凡例の HTML）。API・表示モデル（`ui-view.ts`・`graph-model.ts`）・保存先は変えない。束 `ui-graph-js.ts` は触らない（親が作り直す）。調整の窓・`#meteor=` の比べる用の選びは入れない（「まとめ」の姿だけ）。段階 5（全面の背景）には触らない。
- **置き換え**：本番の彗星（`g-sent` の `.comet`・mask・`linearGradient`・`@keyframes gcomet`・`COMET_TAIL`・`cometSpanOf`・`svg-el.ts` の `comet-*` の id と `url(#…)`）を消し、モックの流星に置き換えて 1 つにする。`svg-el.ts` のタグから `defs`・`mask`・`linearGradient`・`stop` を外し、属性は `pathLength`（100 だけ）と `transform`（`translate(x y)` だけ）を足した。クラスは `mh`・`mhc`・`mtl`・`msp`・`weak`・`late`・`fl`・`sk`・`sk2`・`sk3`。
- **どの線に流すか**（`laneShape`）：上りで答え待ち（`l.dir === "up" && l.waiting`）の線は **強い**（流星＋火花）。下りで段が `sent`（届いたか分からない `unknown` は除く＝破線の `g-sent`）の線は **弱い**（流星のみ）。済んだ子の線・それ以外は流さない。上限は上り 3 本・下り 2 本で、`capMeteors` が、`ago.at`（送った時刻）の新しい順に選ぶ（時刻のない線は最後）。強い流星の 2 本目以降は、半周期ずらす（`late`。モックの `.mt-late`）。
- **流星**：線と同じ `d` の重ね線を 3 本（尾 `mtl`・頭 `mh`・白い芯 `mhc`）、`pathLength=100` で破線の位置（`stroke-dashoffset`）を `@keyframes mt-h`・`mt-hc`・`mt-t` で動かす。本番の上り `d` は子から親へ、下り `d` は親から子へ書いてあるので、道を逆向きに書く必要はない。強い：頭 6・光 2 重・芯 2.6・尾 5 で 45%・1.2 秒。弱い（`.weak`）：頭 4・光 1 重・芯 1.6（80%）・尾 3.5 で 30%・1.8 秒。色は線の色（`--c`。上り・下り・答え待ちの既存の変数を、`.mh,.mhc,.mtl,.msp` にも当てる）。
- **火花**：強い流星の道の終わり（`meteorEndOf(d)`。上りは親の幹の矢印の根元）に `g.msp`（`transform="translate(x y)"`）を置く。中は閃光 `path.fl` 1 つと光の筋 `path.sk` 16 本（形は `SPARK_FLASH`・`SPARK_STREAKS`。流星の来た向き＝右側へ跳ね返る。寿命 3 種）。下りの火花は「まとめ」では出さない。
- **箱の縁の光**：本番の箱は HTML の `.gnode` なので、モックの SVG の `stroke-width` の代わりに `box-shadow` を動かす。`.gnode.t-turn`（答え待ち。`--kaki-line`）と `.gnode.s-fail`（失敗。`--shu-line`）に、`mt-glow`（1 つ目の影 1px → 縁の外へ 1px の輪と 5px の光、1.6 秒、往復）。触れたとき・焦点のとき（`:hover`・`:focus-visible`）は、ふだんの縁にする。
- **動きを止める**：`.still *` と `@media (prefers-reduced-motion: reduce)` の `animation:none!important` で、箱の光は出ない（縁はふだんの太さ 2・光なし）。流星・火花は、破線が周期で並び、animation を切るだけだと線の上に止まって見えるので、`display:none`（`.still :is(.mh,.mhc,.mtl,.msp)` と、reduce の `@media` の中）。
- **色**：直書きなし。白は新しい変数 `--glint`（明・暗とも `#fff`。`--on-strong` は暗で濃い色になるため使えない）、火花の白の混ぜ方は `--sk-w1`・`--sk-w2`・`--sk-wf`（明 45・22・55%、暗 70・40・80%）で、いずれも `:root` の 3 か所（明・暗の media・`.theme-dark`）の定義に置いた（流星・火花・箱の光の CSS 本体には色の値を書かない）。`color-mix` は段階 1 の決めのとおり、使えない古いブラウザは対象外。
- **凡例**：4 項目（`legend.meteorStrong`・`legend.meteorWeak`・`legend.glow`・`legend.meteorStill`。日英）。見本は CSS の `linear-gradient`・`box-shadow` で描く（`.sw.mtsw`・`.sw.mtsw.soft`・`.sw.mtglow`）。モックの「強い流星と火花：判断・失敗」は、本番の線の色が上り＝青・下り＝緑・答え待ち＝橙の 3 つで、失敗（朱）の線を持たない（表示モデルを変えない決め）ので、「あなたの答え待ちの頼み」とした。失敗は箱の縁の光で示す。
- **本番とモックの違い（意図したもの）**：①比べる用の選び・微調整の窓・`#mt-note`・`.mt-cap` の JS はない（本数の上限は `capMeteors`）。②火花の当たる点は、モックの左の出入口の帯でなく、本番の上りの道の終わり。③モックの「失敗の線（朱）」は、本番では箱の光だけで示す。④モックの始まりの位相（`-1.04s`・火花 `-.08s`）は、そのまま持ってきた（読み込み直後の 1 枚に流星と火花が写る）。

# 7. 確かめ（段階 3）

- 試験：`path.test.ts` に、矢印が開いた山形（`Z` なし・`M` が 2 つ・底が先から `ARROW`）であることを足した。`ui-assets.test.ts` に、関係図の CSS（線の `--c` の 4 色・実線が基本・箱が `--sheet`・済んだ子は中だけ薄く・凡例の丸薬）と、色の直書きがないこと（彗星を除く）、凡例の破線の説明を足し、`.line.g-sent` の確認を新しい書き方に替えた。
- `pnpm build` と `pnpm test` は全て通る（daemon は 3 ファイルが skip。ブラウザ試験は環境により走らない）。束 `ui-graph-js.ts` はこの子では作り直していない（親の担当）。
- 届いた線（`g-delivered`）の animation（`gflow`）は、モックの実線に動きがなくても、既存のブラウザ試験（`browser.test.ts`）の期待に合わせて戻した。実線に dasharray はないので、見た目は動かない。
- ブラウザでの目視（明・暗・スマホの幅・日英・キーボード・動きを止める設定）は**未確認**。特に、実線にした線と山形の矢印の見え方、済んだ子の薄さ、等幅の札が線に重ならないこと、箱の縁の色の区別を、人が確かめる。daemon の試験は 3 ファイルが skip された（ブラウザを使う試験と見られるが、どれかは確かめていない）。ブラウザを使う試験が走っていないものとして扱う。
