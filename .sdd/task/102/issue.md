# 統合が受信箱の項目を受け取ったことを記録する（子 → 親のやり取りの「届いた」を出すため）（v0.1.6 に入れる）

## 背景

#89（状態画面の作り直し）で、やり取りの図の動きを「やり取りの進み具合」に結びつけることにした。やり取りごとに、`sent`（送った・まだ届いていない）→ `delivered`（届いた・返事を待っている）→ `done`（済んだ）の段を持たせ、段に合わせて線の流れ方を変える。

#89 の調べ（`.sdd/task/issue-89/research.md` の 9 節）で、次のことが分かった。

- 親 → 子の指示は、送った（`node.instructed`）と届いた（`node.instructionDelivered`。子が `child.inbox` の `ackThrough` で受け取りを返したとき）が記録にある。
- 子 → 親の報告・判断の頼み・範囲の広げの頼みは、送ったは記録にあるが、**統合が受信箱で受け取った（読んだ）ことは記録にない**。`inbox.fetch` は読むだけで、SSE の知らせも記録しない。
- そのため、子 → 親のやり取りは「届いたかは分からない」としか見せられない。

## やりたいこと

統合が受信箱の項目を受け取ったことを記録し、子 → 親のやり取りの「届いた」を、状態画面に出せるようにする。

## 案（#89 の調べから）

- 統合の `inbox.fetch` に、子と同じ作りの `ackThrough`（ここまで受け取った）を持たせ、新しいイベント `inbox.acknowledged` を記録に積む。
- 表示モデルの `flows`（#89 で足す、やり取りごとの段と時刻）で、子 → 親のやり取りの `delivered` を、このイベントから導く。それまでの `deliveryUnknown` の印を外す。
- 統合の skill（`plugin/skills/integrator/SKILL.md`）の、受信箱の読み方の案内を合わせる。

## 決めること

- 受け取りを返すのを、統合の読み方の決まり（skill）に任せるか、`inbox.fetch` で自動に返すか。
- 古い daemon・古い plugin との組み合わせのとき（`ackThrough` を送らない統合）の扱い。

## 受け入れ基準

- [ ] 統合が受信箱の項目を受け取ると、記録に残り、daemon を起動し直しても保たれる
- [ ] 状態画面で、子 → 親のやり取りが「届いた・返事を待っている」の段になる
- [ ] 受け取りを返さない統合では、いままでどおり「届いたかは分からない」になる
- [ ] 仕様（`.sdd/`）・docs・CHANGELOG を合わせ、`bash scripts/check.sh` が通る
