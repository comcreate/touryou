# #249 範囲拡張の依頼を、通らないと分かった時点で断る

## 課題

`scope_extend` の依頼は、記録されて承認の画面に出る。しかし、収まるかの検査（`checkApprove`）は人間の判定の後に走るため、
どう承認しても `scopeNotSubset` で失敗する依頼（例: 許可が `bash scripts/fetch-actionlint` なのに子の頼みが
`scripts/fetch-actionlint`）が、押せるボタンつきで出る。失敗の返事から、近い許可も分からない。

## 設計

検査は「判定の時点」から「要求の時点」にも置く（同じ関数 `checkApprove` を使う。検査の規則を 2 か所に書かない）。

1. `scope.extend`（要求）で `checkApprove` を人間の判定として走らせ、次の失敗だけは、記録・受信箱への項目なしに子へ返す。
   - `scopeNotSubset`: 拡張後の範囲が親（根は rootScope）に収まらない。
   - `scopeDenied`: MCP ツールが deny に当たる。
   - `scopeInvalid`: 作業ツリーの規則を満たさない。
2. 例外: 親が根で、規則に直せる（`addableLimitRule`）依頼は、人間が「上限にも足して承認」（#194 PR4）で通せるので、今までどおり画面に出す。
   親が根でない（上限を人間が広げられない）、規則に直せない依頼は断る。
3. 一時的な失敗（`worktreeUnknown`・`rootScopeUnconfigured`・`notFound`）は、要求では断らず、判定のときの検査に任せる。
4. 近い許可コマンドの提案は、読み取りだけの純関数 `nearestAllowedCommand`（`packages/core/src/scope.ts`）に置く。
   許可の語の並びの末尾が依頼と同じ、または依頼の末尾が許可と同じものを返す。`commandCovers`・`isScopeSubset` の前方一致の規則は変えない。
   `scopeNotSubset` の失敗の文（要求の拒否と判定の失敗の両方）に「近い許可コマンド: …（この形で頼み直す）」を添える。

## 却下した案

- 要求の時点で、収まらない依頼をすべて断る: 人間の「上限にも足して承認」の道が無くなる（#194 PR4 の機能の退行）。
- 前方一致を末尾一致に緩める: 許可の意味が広がる（権限の拡大）。提案にとどめる。
- 画面でボタンを無効にする: HTML の見た目の変更になる。daemon で断れば、画面には出ない。

## 画面（HTML）への影響

変更なし。「上限にも足して承認」で通せる依頼の画面の文言の追加は、見た目の変更が要るかどうかを確かめられていないため、行わない（報告に記載）。
