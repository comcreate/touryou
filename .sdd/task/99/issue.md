# 状態画面と CLI から、人が受信箱の項目を片付けられるようにする（v0.1.6 に入れる）

## 背景

状態画面（`/ui`）と受信箱には、人が項目を「片付ける（済んだにする）」操作がない。記録には `inbox.resolved` があるが、人が呼べる操作がない。そのため、済んだ・読んだ項目が残り続け、子の「要対応」の数が増える一方になる（#89 の調べで分かった）。

#89 では、済んだ子・アーカイブした子の項目を**たたむだけ**にすると決めた（#89 の D6）。人が片付ける操作は、この Issue で扱う。着手は #89 のあと。

## やりたいこと

人が、状態画面と `touryou` コマンドから、受信箱の項目を片付けられる。片付けた項目は「要対応」の数に入らない。

## 案（#89 の調べ `.sdd/task/issue-89/research.md` の 6.4 から）

- 操作 `inbox.resolve`（`{ itemIds: string[] }`）を足し、記録に `inbox.resolved` を積む。呼べるのは人間（統合ノードは自分の部分木だけ、とするかは決める）。
- 画面：カードの項目に「片付ける」、カードに「この子の済んだ項目をまとめて片付ける」。片付けた項目は「片付けた項目」にたたんで残し、戻せるようにする（取り消せるので、ID の打ち込みの確認は要らない）。
- 片付けてよい種類：`progress`・`done`・`info`。`decision`・`violation`（拡張要求が未判定のもの）・`stopIncomplete` は、答える・宣言するまで片付けさせない。
- CLI：`touryou inbox resolve <項目 ID>…`。

## 決めること

- 戻せるようにするか（記録に `inbox.reopened` を足すか）。
- 片付けた項目を消す時期。
- 統合ノードにも片付けを許すか。

## 受け入れ基準

- [ ] 画面と CLI から、片付けてよい種類の項目を片付けられる。片付けてはいけない種類は断られる
- [ ] 片付けた項目は「要対応」の数に入らない
- [ ] 片付けは記録に残り、daemon を起動し直しても保たれる
- [ ] 仕様（`.sdd/`）・`docs/ui.md`・`docs/cli.md`・CHANGELOG を合わせ、`bash scripts/check.sh` が通る
