# 状態画面を確定したモックの見た目に作り直す 決定ログ

見た目の基準は、#238 で確定した `docs/ui-mock/`。描画の層だけを変え、daemon の窓口・表示モデル・保存先は変えない。

## 2026-11-24 状態画面の作り直しは 5 段階に分け、各段階で単独にマージできるようにする（#236・#254）

- **Decision**: 段階は、1 色・面・上のバー・設定と管理の窓、2 三つの窓とタブと幅の区切り、3 関係図の作り直し、4 流星・火花・枠の光、5 全面の背景（WebGL）と docs・CHANGELOG の最終の直し、の 5 つにする。各段階で `pnpm build`・`pnpm test`・`scripts/ui-browser-check.mjs` が通り、単独でマージできること。
- **Rationale**: 利用者の決定（段階分け）。段階ごとに戻せるようにし、一度に大きく変えない。
- **Rejected alternatives**: None considered.

## 2026-11-24 本番の彗星は、モックの流星に置き換えて 1 つにする（#236 段階 4）

- **Decision**: 本番の彗星（`g-sent` の `.comet`）を、モックの流星に置き換えて 1 つにする。
- **Rationale**: 利用者の決定（彗星と流星）。流れの表し方を 1 つにし、2 つを並べて見せない。
- **Rejected alternatives**: 彗星と流星を両方残す（1 つにする決定に反する）。

## 2026-11-24 `color-mix` を使い、`color-mix` が使えない古いブラウザは対象外にする（#236）

- **Decision**: 色の混ぜ方に `color-mix` を使う。`color-mix` が使えない古いブラウザは、対象外とする。
- **Rationale**: 利用者の決定（`color-mix` は、使えない古いブラウザを対象外にする）。
- **Rejected alternatives**: None considered.

## 2026-11-24 管理（最終削除・捨てた作業の保管・取り消せない操作の確認）は、設定の窓から開くダイアログに入れる（#236 段階 1）

- **Decision**: 設定の窓の下の「管理（取り消せない操作を含む）」から開く。押すと設定を閉じてから管理を開き、窓は重ねない。管理の窓の中に、最終削除・捨てた作業の保管・確認の欄（`#confirm-admin`）を置く。管理の窓が開いているあいだ、確認は窓の中に出す。
- **Rationale**: 利用者の決定（管理はダイアログにし、取り消せない操作の確認の欄も管理の窓の中に出す）。
- **Rejected alternatives**: 設定の窓の中に管理を並べる（段階 1 の設計で、窓を重ねず、管理を別の窓にした）。

## 2026-11-24 調整の窓（モック専用の微調整）と、比べるための選びは本番に入れない（#236）

- **Decision**: モックの調整の窓・比べるための選び（`#meteor=`）・その説明の欄（`#mt-note`）・本数の表示（`.mt-cap`）の JS は、本番に入れない。本数の上限は、本番の決めた関数（`capMeteors`）だけで決める。
- **Rationale**: 利用者の決定（調整の窓はモック専用）。
- **Rejected alternatives**: None considered.

## 2026-11-24 窓の中のモックのタブは入れず、承認・確認・知らせは窓の外に置く（#236 段階 2）

- **Decision**: モックの窓の中のタブ（左の「判断・答え待ち／受信箱の知らせ」、右の「選んだ作業／作業の一覧」）は入れない。承認の欄（`#approvals`）・確認の欄（`#confirm`）・知らせ（`#notice`）は、どのタブを出していても見えるように、窓の外（舞台の上）に置く。
- **Rationale**: 本番に対応する中身（受信箱だけの一覧・選んだ作業の詳しい欄）がなく、表示モデルを変えない決めのため。
- **Rejected alternatives**: モックのタブを入れる（対応する中身と表示モデルの変更が要る）。

## 2026-11-24 済んだ子の札は、文字の色で薄くし、`opacity` では薄くしない（#236 段階 3）

- **Decision**: 済んだ子の札の文字は、色（`--muted`。4.5:1）で薄くする。済んだ線・矢印・端子は、`--wire-over`（3:1）に `opacity:.45` を重ねたままにする。
- **Rationale**: PR #268 のレビューで、札の文字を `opacity` で薄くすると読めなくなる指摘を受けたため。
- **Rejected alternatives**: 札の文字を `opacity` で薄くする（PR #268 のレビューの指摘で不採用）。

## 2026-11-24 関係図の札は、固定幅の札の地を使わず、図の地の色の縁取りで読めるようにする（#236 段階 3）

- **Decision**: 線の上の札は、等幅 12.5px の文字で、文字の色（`--ai`・`--matsu`・`--kaki`・`--muted`。4.5:1）を使う。札の地は付けず、図の地の色の縁取り（`paint-order:stroke`）で読めるようにする。
- **Rationale**: 本番では、文字の長さが言語と時刻で変わり、「何分前」の更新で札の幅が合わなくなるため、固定幅の地を持てない。
- **Rejected alternatives**: モックの固定幅（116px）の札の地を使う（本番の文字の長さに合わない）。

## 2026-11-24 流星は、答え待ちの上りの線に強い流星と火花、届いた下りの線に弱い流星を流す。上限は上り 3 本・下り 2 本とする（#236 段階 4）

- **Decision**: 上りで答え待ちの線は、強い流星（火花つき）を流す。下りで届いたかが分かっている（破線の `g-sent` でない）線は、弱い流星を流す。済んだ子の線と、それ以外は流さない。上限は上り 3 本・下り 2 本とし、送った時刻の新しい順に選ぶ（時刻のない線は最後）。強い流星の 2 本目以降は、半周期ずらす。
- **Rationale**: 答え待ちは、利用者が最初に見るべきものなので、いちばん目立つ強い流れにする。本数を抑えて、関係図を読めるままにする。
- **Rejected alternatives**: None considered.

## 2026-11-24 失敗は流星の色ではなく、箱の縁の光で示す（#236 段階 4）

- **Decision**: 失敗（朱）の線は持たない。失敗は、箱の縁の光（`--shu-line`）で示す。凡例の「強い流星と火花」は、答え待ちの頼みの説明にする。
- **Rationale**: 表示モデルを変えない決め（線の種類に失敗を足さない）。
- **Rejected alternatives**: 失敗の線を朱で流す（表示モデルの変更が要る）。
